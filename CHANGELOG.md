# Изменения

## 0.12.0

Переход к видимой профессиональной команде: квалификации ролей, наблюдения ресурсов, объяснимые предложения и мастер настройки. Применение настроек, согласие владельца и запуск работы выполняются отдельно; автопилот по умолчанию выключен.

- Команды `team show|plan|propose`, `resources record`, `executor fingerprint|qualify`; русский интерфейс и JSON.
- Оценки закреплены за моделью/конфигурацией, инструкцией/навыками/схемой роли, материалом оценки и сроком. Это импортированное заключение, а не автоматический benchmark или приёмка задачи.
- Ресурсы по единицам и областям, общие quotaGroup, сроки и явные неизвестные остатки; каталог ссылок для проверки бесплатного доступа без выдуманных квот.
- Независимое ревью резервируется вне всех пишущих кандидатов и их fallback. Новые пулы повторно проверяют роль и актуальность данных перед запуском.
- Старые предложения не перезаписывают новые настройки; отпечатки зависимостей и срок, последовательные операции настроек. Предложения без baseDigest требуется пересоздать.
- Исправлена ложная успешность пробы отсутствующей command; Retry-After повторяется не более одного раза на исполнителя.
- Мониторинг тишины не запускает перекрывающиеся опросы: медленная запись на Windows больше не создаёт несколько вопросов и не теряет ответ об остановке.
- История попыток сохраняет модель, endpoint и свидетельство запуска. TEAM.md и диспетчерская поясняют отдельную приёмку.
- Новая роль design-prompter; консолидированная архитектура, технический аудит, форматы, README и новые схемы на шести языках.
- Мастер `setup` / `мастер`: диалог в терминале и шаги без TTY из приложения; сохранение выбора, конкретные модели, проверка совместимости и независимости, SETUP.md. Поиск файлов CLI не запускает команды или API. Предложение связано с выбором и инструкциями ролей; применение и запуск отдельны.
- CI дополнен macOS; реальное качество моделей и нативное исполнение на телефоне не подтверждаются этими тестами.
- Стенд оценки конкретной модели/роли с fixtures, действующими skills, независимыми проверками и учётом расхода; сравнение тарифов только при сопоставимом наборе.
- Общий execution ledger, резервы tokens/USD, WIP, UNKNOWN после обрыва, явная сверка владельцем; зависимости задач и checkpoints консолидации.
- Passkey/WebAuthn для настроек и критических вопросов: доверенное сопряжение, exact origin/RP, UV/UP, expiry, nonce, revision, revoke и аудит вне проекта; первоначальное сопряжение отдельно.
- Управляемый монитор с start/stop/status, heartbeat и пределом циклов; предложения без автоматического применения или запуска.
- Gemini CLI с deny-all policy и API generateContent для JSON/PNG; экспорт инструкций шести сред, локальное расширение VS Code с runtime.
- Роли coordinator, platform-engineer, security-reviewer — всего 21 роль.
- Переносимый набор явных файлов с SHA и повторной проверкой; Dockerfile/Dev Container, VSIX, checksum/provenance и GitHub attestation workflow.
- README и схемы на шести языках, операционное руководство и [контроль реализации](docs/discussions/modernization-2026-10-09.md). Живые модели, телефон/VS Code и опубликованное происхождение подтверждаются отдельно от fixture-тестов.

## 0.11.1 — 2026-10-07

Схемы в README перерисованы заново: старые упрощали устройство Borshkit, а местами описывали его неверно.

- **Новая схема «Устройство»:** кто вызывает `borshkit`, модули `core/` по группам, где лежат файлы (`borshkit/`, `.state/`, копия задачи на своей ветке) и какие бывают исполнители.
- **Путь задачи** показывает все исходы листа приёмки (нужно исправить, не проверено, ждёт тебя, принято), обратные петли и шаги после принятия: `задача обновить`, `собрать`, `отправить`.
- **Доказательства:** пять отпечатков состояния, из которых складывается сверка, и поля записи доказательства.
- **Выбор исполнителя:** четыре фильтра по порядку, исходы запуска (лимит, тишина, сбой) и критическая остановка.
- **Знания:** источники, сборка в `knowledge/_generated/` и `.state/kb.sqlite`, кто читает индекс; направления связей `tests` и `about` исправлены.
- Все схемы на шести языках, в светлой и тёмной теме; без анимации при `prefers-reduced-motion`.
- **Архив в релизах и счётчик скачиваний.** К каждому релизу автоматически прикладывается `borshkit.tgz`; поставить можно одной командой `npm install -g https://github.com/ParkPavel/borshkit/releases/latest/download/borshkit.tgz`. Счётчик в README считает скачивания этого архива.

## 0.11.0 — 2026-10-07

Исправлено всё, что нашёл независимый аудит 0.10.1 — подробно в [ответе на аудит](docs/discussions/audit-2026-10-07.md). Каждое исправление закреплено тестом, который падал на 0.10.1.

- **Ревью** привязано к состоянию, которое видел ревьюер; импортированное ревью и ревью неизвестного семейства моделей сами ничего не принимают.
- **Сборка** принимает ровно то, что попадает в основную версию: новая команда `задача обновить`, `собрать` отказывает, если основная версия ушла вперёд.
- **Доверие к моделям** считается по семействам, один случай на ответ человека, решение по верхней границе ошибки.
- **Отправка** проверяет на ключи всё, чего ещё нет на выбранном удалённом репозитории.
- **Снимок состояния** видит бит исполнения и подмодули.
- **Границы записи:** записи API-исполнителей проверяются по `paths`; без Git пишущие роли — только с `--в-папке`.
- **Параллельная работа:** один писатель на задачу, сохранения истории пространства по очереди.
- **Сбой с ответом** (ненулевой код завершения) — это сбой; ответ сохраняется для человека.
- **Честные формулировки** приватности и границ карты знаний в README на шести языках, SECURITY и документации.

## 0.10.0 — 2026-10-06

- **Фронтенд, дизайн и iOS.** Четыре новые роли: `ui-engineer`, `ios-designer`, `motion-reviewer`, `a11y-reviewer`. Роль `designer` теперь ломает интерфейс худшими данными.
- **Пакеты навыков.** Навыки Emil Kowalski (14) и фронтенд-навыки ECC (9) скопированы с лицензиями и зафиксированными версиями. Роль получает только свои навыки; другие можно добавить к работе флагом `--навыки пакет/навык`. Новая команда `borshkit навыки`.
- **Библиотека.** 63 проверенные ссылки: компоненты, анимация, дизайн-системы, доступность, иконки, шрифты, инструменты качества. Роли интерфейса получают свою часть списка. Команда `borshkit библиотека [категория]`.
- **Документация как база знаний.** Документация переписана простыми словами и устроена как заметки Borshkit. Её читает GitHub, Obsidian рисует граф, а Borshkit строит SQL. Документы проекта с frontmatter Borshkit дают типизированные связи. Граф документации Borshkit собирает сам (`docs/graph/`).
- **SQL-выгрузка графа:** `borshkit знания экспорт --sql граф.sql`.
- **README на шести языках:** русском, английском, немецком, корейском, традиционном китайском и французском. Анимированные схемы на каждом языке, с тёмной темой и уважением к настройке «меньше движения».
- **Рецепт.** `docs/ingredients.md` вместо `docs/lineage.md`: все ингредиенты, включая пришедшие через Claudex (Spec Kit, Superpowers, Graphify, prompt-agent, HIGAgentSkills). Список контрибьюторов дополнен до 1262 записей.

## 0.9.0 — 2026-10-06

Весь стек из спецификации собран и проверен тестами (66+) на Linux и Windows.

- **Пространство:** папка `borshkit/` в корне проекта — хранилище Obsidian со своей локальной историей Git; правило игнорирования добавляется и проверяется автоматически; работа в папках без Git.
- **Приёмка по целям:** цели, критерии `auto` / `model` / `manual`, доказательства, привязанные к точному состоянию; лист приёмки для человека; цели доверия к моделям, подтверждаемые измерением.
- **Материалы и исследования:** копии источников по содержимому, проверка цитат, Jina Reader и инструменты Agent Reach как источники.
- **Приватность:** режимы «умеренный», «строгий», «эксперимент»; настройки через предложения; доверенный агент; правка в обход останавливает записи; журнал ключей эксперимента.
- **Исполнители и работы:** Claude Code, Codex, OpenAI-совместимые API, свои команды; проверка возможностей; пулы с переключением при лимитах и молчании; 13 ролей; линза «ленивый сеньор» (Ponytail); отдельная копия проекта для пишущих ролей.
- **Автопилот и диспетчерская:** рутинные вопросы с ответом по умолчанию, критическая остановка с отчётом и передачей контекста; `STATUS.md`, `status.html`, строка статуса.
- **База знаний:** заметки с типизированными `[[связями]]`, SQL-индекс только на чтение, срез контекста, уроки с контролем устаревания, экспорт для GitHub.
- **Атрибуция:** проверки `attribution` и `readme-assets`, полный список контрибьюторов референс-проектов (`CONTRIBUTORS-REFERENCES.md`).
- **Git для новичка:** история, изменения, авторство, возврат с копией, сборка принятой задачи, отправка без перезаписи чужого.
- **Плагин Claude Code:** маркетплейс, hooks (только в проектах с пространством), skill; `AGENTS.md` для Codex и других агентов.
- **Оценка:** ложные PASS по скрытым проверкам, вмешательства, расход; измерение доверия к моделям.
