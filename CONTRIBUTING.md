# Как помочь Borshkit

Спасибо, что хочешь помочь! Вот несколько правил, чтобы изменения принимались легко.

## Перед тем как начать

- Прочитай [AGENTS.md](AGENTS.md): там стек и инварианты. Они одинаковы для людей и агентов.
- Большую идею сначала обсуди в issue. Проект намеренно маленький: каждый новый слой должен доказать пользу (спецификация, §14–§17).

## Код

- Node.js 22+, ESM, никаких зависимостей времени выполнения.
- Тексты для пользователя — по-русски и простыми словами. Код и комментарии — по-английски.
- Ничего разрушающего в Git. Никаких автоматических «принято» без доказательств. Неизвестное — это UNKNOWN.

## Проверка

```sh
npm run verify
```

Новое поведение — вместе с тестом. Временные Git-проекты и поддельные исполнители лежат в `test/helpers.mjs` и `test/fixtures/`. Платные модели в тестах не вызываются.

## Документация и переводы

- Документация — в `docs/`, в формате заметок Borshkit: [как устроено](docs/concepts/knowledge.md). Проверь, что ссылки живые: тест `docs` это сверяет.
- README есть на шести языках. Меняешь смысл в `README.md` — поправь и переводы (`README.en.md`, `README.de.md`, `README.ko.md`, `README.zh-TW.md`, `README.fr.md`), либо явно попроси помощи с переводом в PR.
- Подписи на анимированных схемах живут в `scripts/diagrams.mjs`. После правки запусти `node scripts/diagrams.mjs`.

## Чужой код, навыки и благодарности

Переносишь чужой код или тексты? Укажи источник в файле и добавь его в [`third-party.json`](third-party.json) и [`docs/ingredients.md`](docs/ingredients.md). Навыки кладутся в `packs/<пакет>/` с лицензией автора и `pack.json`. Проекты без лицензии можно только упоминать.

Проверка должна проходить: `borshkit атрибуция проверить --readme docs/ingredients.md`.
