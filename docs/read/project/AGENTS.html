Для агентов, которые разрабатывают Borshkit#

  • Стек: Node.js 22+, ESM, никаких зависимостей времени выполнения — npm run check это проверяет. Только встроенное: node:sqlite, node:test, fetch.

  • Язык: всё, что видит пользователь, — по-русски и простыми словами. Имена в коде и комментарии — по-английски.

  • Перед коммитом: npm run verify — статические проверки и все тесты. CI запускает то же самое на Linux, Windows и macOS.

  • Тесты создают временные Git-проекты и поддельных исполнителей (test/fixtures/). Платные модели в тестах не вызываются.

  • Инварианты (спецификация docs/spec.md, §13):

    • «готово» от модели — не приёмка;
    • доказательство действует только для своего состояния;
    • неизвестное — это UNKNOWN, а не PASS;
    • ослабить защиту может только человек;
    • ничего разрушающего в Git.

  • Чужой код и тексты: перенося код из Claudex, оставь в файле пометку «adapted from Claudex … (Apache-2.0, same author)». Новый внешний источник добавь в third-party.json и docs/ingredients.md. Навыки кладутся в packs/<пакет>/ вместе с LICENSE и pack.json. Проверка attribution всё это сверяет.

  • Сгенерированные файлы не правь руками, а пересобери:

    • library/README.md — node scripts/library.mjs;
    • assets/diagrams/*.svg — node scripts/diagrams.mjs;
    • docs/graph/ — node scripts/docs-graph.mjs.

    Тесты падают, если первые два устарели.

    • docs/read/ и docs/media/ — npm run site; проверка актуальности — npm run site:check.

  • Документация — заметки в формате Borshkit: frontmatter с bk-type и связями-путями, внизу раздел «Связи» с обычными ссылками (как устроено).

  • В проекте с пространством Borshkit пользуйся навыком skills/borshkit/SKILL.md.
