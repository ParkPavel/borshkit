Безопасность#

Как сообщить об уязвимости#

Не публикуй уязвимость в открытом issue. Используй приватное сообщение об уязвимости на GitHub или напиши владельцу репозитория.

От чего Borshkit защищает и где защита заканчивается#

Угроза Защита Граница
Ключи уходят к модели пакет для исполнителя проверяется до отправки; дочерние процессы получают только разрешённые переменные окружения поиск по шаблонам ловит не всё
Агент читает .env пишущие роли работают в отдельной копии (git worktree), куда игнорируемые файлы не попадают агент, запущенный прямо в корне проекта, видит всё, что разрешают его собственные права
Агент читает файлы проекта после отправки задания в копии нет игнорируемых файлов; строгий режим допускает только исполнителей local и no-train Borshkit проверяет только задание, которое отправляет сам. Что Claude Code или Codex читают из отслеживаемых файлов копии, он не видит и не фильтрует
Ключи в окружении исполнители получают только разрешённые переменные окружения проверки задач (тесты, сборка) запускаются с твоим полным окружением — тестам бывают нужны ключи
Агент пишет за границы задачи записи API-исполнителей проверяются по paths задачи до записи; запись в .git и в папку пространства запрещена; сверка находит правки вне границ (в проекте без Git — по хешам файлов) агенты-CLI пишут сами: их правки вне границ видны только при сверке, а не предотвращаются
Агент ослабляет защиту настройки меняются только через предложения; ослабление — после терминальной фразы либо проверенного passkey; действие и ревизия связаны подписью, nonce одноразовый; правка в обход замечается терминальная фраза — барьер UX; passkey требует доверенного первоначального сопряжения, HTTPS и реестра вне доступной агенту области; владелец ОС может обойти код сервиса
Потеря работы нет reset --hard, принудительной отправки и удаления веток; «вернуть» сначала сохраняет копию —
Ключ в истории проекта сохранить-проект проверяет изменения на ключи; отправить проверяет все коммиты, которых ещё нет на выбранном удалённом репозитории только известные форматы ключей
Ложное «готово» приёмка по доказательствам, привязанным к состоянию; ревью привязано к состоянию, которое видел ревьюер; импортированное ревью и ревью неизвестного семейства моделей сами ничего не принимают; собрать можно только то, что принято вместе с текущей основной версией доказательство показывает только то, что измеряет проверка
Навык из чужого пакета влияет на работу навыки подключаются только к своей роли или по флагу --навыки; чужие хуки не ставятся; текст пакета зафиксирован по версии и виден в репозитории навык — это инструкция модели; что в нём написано, решает его автор

Хуки Claude Code — второй, советующий слой, а не песочница.

Удалённое подтверждение и поставка#

Руководство описывает RP/origin, подписи, отзыв, сроки, негативные проверки и границы доверия. Реальный телефонный браузер и HTTPS требуют отдельного испытания; чтение кода и криптографические fixture-тесты не являются pentest. Локальные checksum и provenance не являются подписью сборки; GitHub attestation доступна после успешного workflow выпуска.
