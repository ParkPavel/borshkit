Команда, оценки ролей и ресурсы#

Первый этап модернизации добавляет объяснимые предложения поверх существующих исполнителей и пулов. Он не включает автопилот, не подключает API автоматически и не запускает работы при применении пула.

Порядок действий#

  1. Создай пространство и задачу обычным способом. Зафиксируй явную модель в манифесте исполнителя; для API укажи baseUrl и только имя переменной ключа.
  2. Проверь подключение: borshkit исполнитель проверить <имя>. Проверка CLI читает help/version, API — список моделей. Она не проверяет качество, успешность генерации или реальные возможности всех инструментов.
  3. Проведи оценку роли на своих заданиях. Сохрани метод, модель, окружение, примеры, критерии, ошибки и заключение в assessments/<имя>-<роль>.md. Без фактической оценки не записывай PASS.
  4. Предложи запись оценки, затем примени её обычным процессом настроек. Повтори для необходимых ролей и исполнителей.
  5. Запиши известные ресурсы либо оставь их неизвестными. Рассчитай и посмотри план. Создай предложение, примени его, затем отдельно запусти роль.
sh
borshkit исполнитель оценить coder --роль implementer --файл assessments/coder-implementer.md --результат PASS --срок 2026-11-01T00:00:00Z
borshkit настройки применить p001
borshkit команда
borshkit команда план моя-задача --роли architect,implementer,reviewer
borshkit команда предложить моя-задача --роли architect,implementer,reviewer
borshkit настройки применить p002
borshkit работа запустить моя-задача --роль implementer --пул team-implementer
borshkit работа запустить моя-задача --роль reviewer --пул team-reviewer
borshkit задача итог моя-задача

p001 и p002 — примеры; используй выданные номера. Срок должен быть в будущем. Добавление/изменение исполнителя и расширение пула обычно ослабляют защиту и требуют подтверждения владельцем в терминале либо сопряжённым passkey. После доверенного сопряжения настройки и критические вопросы можно подтвердить passkey с телефона: операционное руководство.

Английские команды: team show|plan|propose, resources record, executor fingerprint|qualify. Флаги: --roles, --role, --file, --result, --until, --json. resources show показывает общий каталог команды; назначенные пулы и их роли видны там же.

Манифест исполнителя#

Новые необязательные поля:

  • service — сервис доступа, например groq или openrouter; нужен для связи с каталогом кандидатов.
  • provider — существующее поле семейства самой модели, например meta для Llama через Groq. Разные API-посредники с одной моделью не дают независимого ревью. Семейство задаёт человек; Borshkit не удостоверяет его автоматически.
  • quotaGroup — явно общая группа ресурсов. Без неё каждый исполнитель учитывается отдельно. Разные ключи одного аккаунта могут расходовать общий лимит; группу надо указать правильно.
  • qualifications — оценки по ролям, создаваемые командой executor qualify.

Запись оценки содержит result: PASS|FAIL, at, expiresAt, fingerprint конфигурации исполнителя, roleDigest инструкции/навыков/схемы роли, относительный путь evidence и SHA-256 evidenceSha. Разрешены md/json/txt внутри проекта, без скрытых путей; symlink не может вывести чтение наружу. Отпечаток можно посмотреть командой executor fingerprint.

Изменение конфигурации модели, промпта роли, пакета её навыков, схемы или материала оценки делает запись устаревшей. Локальный отчёт остаётся заявлением оценившего человека. Ни криптографическая аттестация benchmark, ни проверка его статистической достаточности сейчас не выполняются.

Наблюдение ресурсов#

json
{
  "scope": "account",
  "at": "2026-10-08T12:00:00Z",
  "expiresAt": "2026-10-08T13:00:00Z",
  "metrics": [
    { "name": "tokens", "window": "subscription", "remaining": 12000 },
    { "name": "usd", "window": "balance", "remaining": 2.5 }
  ]
}

Даты в примере заменяются реальными. Запись: borshkit ресурсы записать coder --файл resources.json.

Поле Значение
scope account или endpoint
endpoint обязателен для endpoint, например chat/completions
name requests, tokens, images, usd, contextTokens, memoryBytes
window rate, subscription, balance, context, local
remaining, limit неотрицательный остаток; необязательный лимит не меньше остатка
resetAt необязательное будущее время сброса

Импорт получает источник DECLARED. Распознанные x-ratelimit-* заголовки API — HTTP_HEADERS, срок 60 секунд или до сброса, если он раньше. Число токенов в ответе — расход попытки, а не баланс. Неизвестные поля импорта не сохраняются. Ключи хранятся в окружении. Неподдерживаемые заголовки и квоты подписочных CLI остаются неизвестными; автоматическое чтение личных кабинетов не реализовано.

Наблюдения привязаны к конфигурации источника и quotaGroup. Самая новая запись одной области/единицы/окна имеет приоритет; старая не заменяет новую. Endpoint /models не блокирует chat/completions. При истечении срока или сбросе remaining становится null, не нулём и не новым лимитом. Текущие сведения по одной метрике не доказывают известность всех ресурсов.

План и безопасность применения#

Фильтры: полномочия/формат ответа/модальности → приватность → свежая проверка подключения → актуальный PASS оценки роли → ресурсы → независимость. Для каждого отказа показана причина. Среди прошедших кандидатов предпочтение получают свежие сведения; затем используется стабильный порядок имён. Неизвестный остаток сопровождается предупреждением.

Для независимого ревью резервируется семейство, отличное от всех существующих авторов и всех резервных пишущих исполнителей плана. Если распределение невозможно, статус BLOCKED и предложение настроек не создаётся. Если возможно — PROPOSED; создаются пулы team-<роль> с role и qualificationRequired: true.

Предложение привязано к исходным настройкам, контракту, авторству, пробам, ресурсам, материалам оценок и инструкциям ролей. Его срок ограничен самым ранним сроком использованных данных. При изменении зависимостей или срока применение отказывает до запроса подтверждения. Старые предложения без baseDigest также требуют пересоздания, чтобы не перезаписать новые настройки старым полным снимком.

При запуске через такой пул снова проверяются роль пула, оценка, проба и известный нулевой остаток. Дополнительные --навыки и --линза для квалифицированного пула запрещены: оценка относится к базовым инструкциям. Произвольные старые пулы и явный --исполнитель сохраняют прежнее поведение и не становятся автоматически квалифицированными. Свежесть проверяется перед каждой попыткой, но запуск не резервирует токены и не исключает параллельный расход другим клиентом. Ошибка QUOTA вызывает предусмотренную передачу; один исполнитель повторяется по Retry-After не более одного раза в работе.

Представления и мониторинг#

TEAM.md, .state/team.json, STATUS.md и status.html отражают локальные факты. Команда team обновляет каталог; события работы и status --watch обновляют диспетчерскую. HTML автоматически перечитывает файл, но не является сервисом мониторинга и не запрашивает API.

В истории попытки сохранены модель, семейство, тип, endpoint и отпечаток конфигурации. launchedAt появляется после события spawn CLI или ответа API. Для API это подтверждает ответ сервера, но не означает генерацию или успешный результат. При сетевой неопределённости отсутствие подтверждения не доказывает, что сервер не получил запрос. Старые работы могут не иметь этих полей и показываются как неизвестные.

Каталог library/provider-candidates.json содержит официальные ссылки для проверки доступа. CHECK_ACCOUNT означает необходимость проверить условия аккаунта, не бесплатную квоту. Подключение отмечается только для зарегистрированного service и свежей пробы. Нет скрытого подключения, выдуманных лимитов или назначений задач.
