Проверка выпуска 0.13.0#

Реализация пула#

  • Пакет задачи: schemaVersion 1, полный валидный контракт, происхождение контекста, исходное состояние, исторические ссылки evidence, следующие шаги и неизвестное. Round-trip создаёт новую непроверенную задачу и не переносит настройки/приёмку. Повреждение, конфликт имени и секреты отклоняются. Изменение состояния во время упаковки требует повтора.
  • Сжатие: extractive-priority-v1, стабильные приоритеты, дедупликация, SHA и manifest пропусков/обрезки. Фикстура показывает сохранение важного решения в том же бюджете, где обычная обрезка его теряет. Это не оценка качества живой модели.
  • Нативные API: Copilot Language Model API без инструментов, Roo task ID/events/cancel, Cline startNewTask. Отмена чужой Roo-задачи запрещена. Таймаут Copilot отменяет токен; Cline не получает вымышленную отмену или успешный статус. Недоверенный VS Code workspace отказывает до обращения к среде. Запросы связаны с отдельной копией и актуальным состоянием файлов.
  • Языки: JS/TS, Python, Go, Swift; локальные imports/tests и экспортируемые/объявленные символы. Неразрешённые импорты видны. Парсер лексический, без обещания полной семантики компилятора.
  • Живые проверки: скрипт opt-in и формат отчёта. По прямому решению владельца живые модели, аккаунты расширений и физические устройства оставлены пользователям. До запуска статус NOT_RUN; в CI платных вызовов нет.

Прогоны и упаковка#

npm run verify включает статические проверки и все тесты. GitHub CI проверяет точный commit на Node.js 22 в Linux, Windows и macOS; ссылки на конкретный CI и тег находятся в PR и GitHub Release. Отчёт не подменяет статус реального workflow.

Локально собраны и проверены tgz/VSIX: точный tgz установлен в чистую временную папку без install scripts, CLI запущен, проверены версия, новые модули и отсутствие корневых локальных данных. VSIX проверен на manifest и native runtime. scripts/verify-release.mjs повторяет эту проверку на архиве, создаваемом release workflow.

Поиск секретов в пакете проверяется по строковым значениям, а не по JSON целиком: экранированный перевод строки не должен скрывать начало токена. Регрессионный тест сначала выявил проблему и проходит после исправления.

Сайт реально открыт в Chromium на 1440×1000, 390×844 и 320×800: текущая карта из пяти слоёв, целевая из трёх следующих этапов, пояснения, FAQ, отсутствие overflow и runtime errors. Внешний вид и адаптивность просмотрены по скриншотам. Визуальная система сохранена; обновлены версия и фактические возможности.

Сценарии для пользователей#

Для любого живого отчёта нужны версия ОС, Node, Borshkit и расширения/CLI, точный ID модели, минимальный пример, состояние файлов и лог без ключей. Отмечайте расход квоты и UNKNOWN отдельно от дефекта кода.

  1. Copilot: установить VSIX, подготовить задачу, выбрать доступную модель, получить текст, отменить следующий запрос. Убедиться, что файлы не записываются автоматически и приёмка не появляется.
  2. Roo: подготовить и открыть отдельную копию, запустить задачу, проверить ID, событие завершения и отмену. Попытка отмены после переключения на чужую работу должна отказать.
  3. Cline: запустить через API, проверить неизвестный статус в Borshkit и выполнить остановку вручную в Cline. Неподдерживаемая отмена должна дать понятное сообщение.
  4. Телефон: отдельно проверить исходное доверенное сопряжение passkey, origin/RP, отображение действия и отказ повторного подтверждения. Не переносить ключи между устройствами через чат.
  5. Языки: построить карту маленького Python/Go/Swift-проекта, проверить ссылки на реальные файлы и сообщения о внешних/динамических импортах.

Публикация#

Workflow собирает файлы вне checkout и отказывает грязному исходнику. После проверки архива создаются checksum/provenance и подписанное происхождение GitHub OIDC. Публикация draft выполняется после успешной сборки. До успешного workflow и проверки скачанного файла подпись/артефакт не считаются выпущенными.

Реестр npm требует отдельной авторизации npm; GitHub-аккаунт не является такой авторизацией. Установка из GitHub Release через npm поддерживается без публикации в реестр.
