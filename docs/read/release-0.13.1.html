Borshkit 0.13.1 — диагностика запуска и достоверная оценка#

Выпуск объединяет исправления аудита надёжности и обновлённую продуктовую упаковку после 0.13.0. В комплекте CLI, плагин Claude Code и VSIX. Версия не обещает устранение причины аварий пользовательской Windows-машины.

Что изменилось#

  • Ошибки команд показывают код выхода в decimal/hex, сигнал и таймаут. Остановка дерева процессов и ожидание закрытия потоков ограничены по времени.
  • Проба исполнителя различает PASS, FAIL и BLOCKED, сохраняет историю попыток. Только диагностические help/version повторяются один раз при 0xC0000005, EAGAIN, EBUSY или ENOMEM. Рабочие команды этим механизмом не повторяются.
  • API-проба ограничена 30 секундами на запрос и чтение тела. Пустой список моделей не даёт PASS; результаты параллельных проб сохраняются под блокировкой.
  • Скрытые проверки и стенд ролей отличают UNKNOWN инфраструктуры от FAIL результата. Изменение файлов самой скрытой проверкой делает сравнение с прежней приёмкой недействительным.
  • доктор ограничивает проверку Git и больше не подменяет любой сбой сообщением «Git не найден».
  • README на шести языках получили визуальную навигацию, кнопки и поддержку проекта. Документация читается внутри сайта с поиском, оглавлением и копированием команд.

Обновление#

sh
npm install -g https://github.com/ParkPavel/borshkit/releases/download/0.13.1/borshkit.tgz
borshkit помощь
borshkit доктор

VS Code: установи borshkit.vsix из релиза 0.13.1 через Install from VSIX. Для плагина Claude Code обнови установленную копию/пакет до того же тега. У пользователей исходников npm link продолжает указывать на их собственный клон; проверь его версию отдельно.

Миграция форматов задач и настроек не требуется. Настройки, доверие и принятая работа не сбрасываются. Для интеграций, читающих JSON: confirmedQuality теперь равен null, если нет определённых сравнимых проверок; добавлены unknown и evaluated. Проба сохраняет совместимое ok и добавляет status/attempts. Стенд ролей может вернуть UNKNOWN; такой результат нельзя применить как квалификацию.

Известные ограничения: следующий этап#

Исследование условий запуска после аудита выявило два отдельных дефекта, ещё не исправленных в 0.13.1:

  1. childEnv сравнивает имена переменных с учётом регистра. Синтетические Windows-имена Path, SystemRoot, ComSpec отбрасываются. Windows регистронезависима; влияние на конкретный сбой требует испытания на той машине.
  2. Рабочий CLI-адаптер берёт process.env, игнорируя переданное вызывающим кодом env. Диагностическая проба использует переданное окружение. Это воспроизведено с поддельным исполнителем без модели.

Успешные help/version не доказывают готовность полноценной работы: проба не использует фильтр рабочего окружения и рабочие sandbox-флаги. Worktree не переносит автоматически игнорируемые зависимости и локальные настройки. Профили инструментов харнесов ограничены: Claude без Bash/MCP, Codex с заданным sandbox и отключением пользовательской конфигурации, Gemini с запретом инструментов. Это отличается от привычного интерактивного запуска.

Не расширяй окружение всеми секретами и не отключай защиту для обхода проблемы. Перед работой проверь установку зависимостей в копии задачи и необходимые возможности исполнителя. Согласование пробы и рабочего запуска, исправление регистра Windows и единый профиль среды — следующий спринт, не функция этого релиза.

Живые модели, аккаунты VS Code и физические устройства по решению владельца проверяют пользователи. Причина аварии 0xC0000005 не установлена. При отказе ОС завершить потомков ограничено ожидание Borshkit, но исчезновение всех процессов гарантировать нельзя. npm registry и VS Code Marketplace не публиковались; поддерживаемая установка — архив GitHub Release.

Как проверяется выпуск#

npm run verify проверяет код, документацию и регрессии. CI запускает его на Linux, Windows и macOS. Отдельный release workflow устанавливает точный tgz, проверяет состав VSIX и публикует SHA256SUMS, build-provenance.json, release-smoke.json и GitHub attestation. Результаты привязаны к коммиту/тегу, а не к обещаниям качества живых моделей. Ссылки на конкретные прогоны помещены в GitHub Release.
