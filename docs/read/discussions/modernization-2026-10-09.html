Контроль модернизации — 2026-10-09#

Пользователь поручил завершить согласованный пул задач. Изменения выполнены в исходниках ветки 0.12.0. Ни настройка пользовательского проекта, ни автопилот не включались. Статус публикации сверяется отдельно: локальная реализация не доказывает выпуск на GitHub.

Аудит границ#

  1. Доверие. Фразы терминала и доступ к модулю с confirmedByPerson:true не противостоят агенту с произвольными правами ОС. Удалённый протокол опирается на доверенную регистрацию вне агентской сессии и отдельно защищённый реестр/сервис. WebAuthn тестируется криптографическими fixtures; это не pentest и не испытание реального браузера телефона.
  2. Отображение согласия. Страница показывает действительные before/after, вычисленные ослабления и digest; не доверяет изменяемому агентом описанию changes. Смена действия после подписи отклоняется ещё раз под блокировкой настроек/вопроса.
  3. Расход. Ошибки и обрывы не превращаются в бесплатные вызовы. Неизмеренный расход остаётся UNKNOWN; сверка требует владельца. CLI может превысить оценку, поэтому hard billing limit задаётся у провайдера.
  4. Независимость. Качество роли, доступность модели и приемлемость результата — отдельные факты. Стенд не является универсальным рейтингом и не принимает задачи. Тестовый локальный исполнитель не доказывает качество коммерческой модели.
  5. Интеграция. Принятой зависимости с отдельной веткой недостаточно: текущий HEAD зависимости должен входить в проект или копию потребителя. Checkpoint — исторический снимок, после изменений проверяется заново.
  6. Gemini. Первоисточник сообщает, что workspace-tier policies отключены. Adapter использует явный deny-all профиль, sandbox и extensions none, отказывает при стандартных admin TOML и проверяет init-модель. Нестандартная конфигурация или другая версия harness требуют отдельной оценки. API не выполняет function calls.
  7. Перенос. Хеши не подтверждают авторство, а поиск известных секретов не находит все форматы. Capsule — явный перенос файлов, не автоматическое доверие настройкам, старым probes, acceptance или процессам.
  8. Поставка. Docker version tag не закрепляет digest; конфигурация CI не доказывает успешный запуск на macOS. GitHub attestation не существует до успешного workflow. VSIX packaging отдельно от испытания UI в VS Code.

Приёмка поставки#

Локальные проверки запускаются npm run verify; тесты не вызывают платные модели. Конкретные commit, SHA архивов, число тестов и статус GitHub CI фиксируются в отчёте поставки. Для этой execution environment требуется отдельная настройка разрешённого сетевого доступа для HTTP fixtures и внешний тестовый preload против потери pipe stdout; они не входят в продукт. Без этого среды шесть исходных проверок не исполнялись корректно; при разрешённом сетевом доступе предыдущий полный прогон прошёл 136/136. Итоговый прогон после обновления документации и дополнительных проверок фиксируется отдельно.

До публикации исходников, зелёного CI точной версии и успешного release workflow нельзя считать выпущенными ни архив, ни macOS-совместимость, ни подписанное происхождение. Нужны отдельные живые проверки passkey, подписки Gemini и VS Code UI на среде владельца; они не подменяются проверкой упаковки.
