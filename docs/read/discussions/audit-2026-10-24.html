Аудит надёжности и мини-спринт — 24 октября 2026#

Исходное состояние: 8d751d31f04c053bcc847d36405bf5ae74670d64, версия 0.13.0. Перед изменениями локально прошли 183 теста; один Windows-тест пропущен на Linux. Эти числа относятся к исходному состоянию, а не к исправленной версии.

Отчёт пользователя: наблюдения и границы вывода#

Пользователь сообщил о плавающих авариях и зависаниях процессов на Windows: Git, проверки проекта и диагностические запуски CLI. В сообщениях встречается 0xC0000005; Borshkit показывал неинформативное OTHER: Command failed. Прямые запуски той же программы иногда были успешны.

Это подтверждает потребность в диагностике, но не устанавливает причину сбоев. Отдельный успешный запуск не доказывает отсутствие дефекта Borshkit и не равен воспроизведению условий неудачного запуска. Давление памяти, файл подкачки, MSYS2 и защита Windows остаются гипотезами. Изменение исключений антивируса не является исправлением утилиты.

Исходные логи и проблемная машина недоступны. Сведения о стороннем проекте и его продуктовых дефектах не переносились в публичный репозиторий. Регрессионные тесты воспроизводят условия программно, без платных моделей.

Обзор проводился отдельно от выводов отчёта: запуск команд и Git, потоковые адаптеры, проба исполнителей, приёмка, скрытая оценка, квалификация ролей, перенос контекста, импорт файлов, нативные запросы, упаковка и CI.

Мини-спринт решений до правок#

Выбраны ограниченные изменения существующего ядра:

  1. Единый механизм жизненного цикла для обычных команд и потоковых CLI. Сохранить запуск без shell и без повторов рабочих команд.
  2. Диагностический повтор только --help/--version: максимум одна дополнительная попытка при 0xC0000005 (signed/unsigned), EAGAIN, EBUSY или ENOMEM. Таймаут, отмена и обычный ненулевой выход не повторяются.
  3. Явные PASS/FAIL/BLOCKED для пробы, с совместимым полем ok. Сбой измерения не должен доказывать плохое качество модели.
  4. UNKNOWN для недоступной скрытой/стендовой проверки. Изменение файлов самой скрытой проверкой делает сравнение с приёмкой недействительным.
  5. Ограничить API-пробу по времени, проверять присутствие модели, защищать запись результатов проб общей блокировкой.

Критерии: тесты signed/unsigned Windows-кодов без их усечения POSIX, обычный exit 5 остаётся FAIL; завершение при зависшей остановке; факты повторов сохранены; пустой список моделей не PASS; UNKNOWN нельзя применить как квалификацию; полный verify и CI трёх ОС.

Реализовано#

  • core/process.mjs: общие факты ошибки — code, hex, signal, timedOut, reason; stdout/stderr сохранены в пределах бюджета. Команды запускаются без shell и без автоматических повторов.
  • Общий предел вывода — 16 MiB, для проверок приёмки — 8 MiB. Превышение прекращает выполнение и даёт UNKNOWN. У потоковых исполнителей stderr хранится хвостом до 20 000 символов; вывод обрабатывается постепенно, включая UTF-8 между чанками.
  • После таймаута/отмены запрашивается завершение дерева; ожидание закрытия потоков ограничено дополнительными 1,5 с. Windows использует существующий taskkill с fallback. Если ОС не разрешает завершение потомков, Borshkit гарантирует ограниченное ожидание, но не может гарантировать исчезновение всех процессов.
  • доктор ограничивает проверку версии Git десятью секундами и больше не подменяет любой сбой сообщением «Git не найден».
  • Проба хранит историю попыток. При восстановлении CLI сообщает о диагностическом повторе; при невозможности проверить показывает BLOCKED. Обычный ненулевой выход или отсутствие требуемых флагов — FAIL проверки совместимости, не оценка качества модели.
  • API: 30 с на запрос и чтение тела; пустой/неверный список не даёт PASS. Отсутствие модели в корректном списке — FAIL, невозможность прочитать ответ — BLOCKED.
  • Итоги скрытой оценки содержат unknown, evaluated; confirmedQuality равен null, если нет определённых сравнимых проверок. UNKNOWN исключается из знаменателя. При изменении файлов во время проверки сравнение недействительно.
  • Стенд ролей сохраняет UNKNOWN при инфраструктурном сбое. UNKNOWN нельзя предложить в качестве положительной или отрицательной квалификации. Явный FAIL независимой проверки остаётся FAIL.

Проверка и ограничения#

Регрессии находятся в test/process.test.mjs, test/executor-probe.test.mjs, test/api-connect.test.mjs, test/assessments.test.mjs, test/audit.test.mjs. Дополнительно выполняется общий npm run verify; точные результаты и ссылки на CI фиксируются в PR.

Живые Claude/Gemini/Copilot/Roo/Cline, пользовательская Windows-машина и физические устройства не проверялись. Платные вызовы не запускались. Нет установленного диагноза аварии из отчёта. Исправления входят в отдельный выпуск 0.13.1; опубликованный архив 0.13.0 не заменяется.
