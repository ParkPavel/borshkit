25 октября: работа в основной среде и контроль запуска#

Запрос и основания#

Владелец сообщил о перегрузке Windows множеством забытых процессов и локальных MCP при работе через Claude. Логи, замеры памяти и дамп этой машины здесь не исследованы; причинность конкретного падения независимо не подтверждена. При этом отсутствие общего обзора и сложности настройки — самостоятельные проблемы продукта, не зависящие от диагноза падения.

Приоритет согласован: кроссплатформенный доступ из Claude и Codex, прежде всего Claude в терминале VS Code. Изоляция отдельной оболочки больше не обязательный основной сценарий. Исходная версия 0.13.1 сохранена в server/isolated-runtime, коммит 10e4be4a353669d2734e1ce16bb423921e91ca88. Ветка сохраняет старую реализацию; это не заявление о готовности отдельного серверного продукта.

Мини-спринт решений#

Проблема Решение Проверяемая граница
Вложенный агент и изоляция по умолчанию Текущий харнес выполняет работу; Borshkit даёт контракты и проверки Обзор не запускает исполнителя, MCP или монитор
Непонятные команды и подтверждения Меню и инструкции для обычного диалога; точная разница настроек, применить/отмена Digest связывает предложение; согласие доверено разрешениям харнеса
Нет общего состояния Один снимок задач, работ, вопросов, настроек и ресурсов Устаревший heartbeat даёт UNKNOWN; прошлый итог не выдаётся за текущую приёмку
Забытые процессы Общий обработчик сигналов, запрос остановки конкретной работы, освобождение активного слота Нет завершения чужих PID; нет гарантии очистки после принудительного уничтожения родителя
Ложное впечатление резерва памяти Раздельные OS-измерения и учёт токенов/USD Неизвестный счёт не исчезает вместе с процессом
Разное окружение пробы и работы CLI использует переданный env; Windows whitelist учитывает регистр Секреты не наследуются целиком
Ограниченная «команда» Текущему агенту не нужен манифест; дополнительные роли остаются опциональными Произвольный новый протокол требует адаптера; число активных вызовов ограничивается отдельно

Реализация после 0.13.1#

  • core/workspace.mjs — общий снимок и применение показанного предложения настроек.
  • core/workspace-ui.mjs, commands/workspace.md, core/integrations.mjs — терминал, Claude и экспорт инструкций для Codex.
  • core/runtime-control.mjs — запрос остановки с токеном конкретной работы; ограниченное по времени измерение зарегистрированных PID через ps/Get-Process.
  • core/jobs.mjs — владелец, heartbeat, PID, последовательная запись состояния, обработка остановки и освобождение слота.
  • core/process.mjs — общий набор обработчиков сигналов для принадлежащих процессу команд; обработчики снимаются после завершения.
  • core/operations.mjs — восстановление активных слотов завершившихся владельцев; неизвестный расход провайдера остаётся UNKNOWN.

Текущий харнес сохраняет свои разрешения и ограничения. Внутренний env-фильтр применяется к дополнительным вызовам Borshkit, а не изменяет окружение уже открытого Claude/Codex. Старые явные команды дополнительных работ сохраняют worktree и профиль адаптера для совместимости. Они не запускаются автоматически из обзора. Проверка доказательств и запрет автоматической приёмки по словам модели остаются обязательными.

Следующие этапы, ещё не реализованы#

  1. ОС-контейнер владения всем деревом: Windows Job Objects, проверка завершения потомков, восстановление после аварийного убийства родителя.
  2. Измерение всего дерева, пороги CPU/RAM и выбранная человеком политика реакции. Сейчас измеряется корневой зарегистрированный PID; повторное использование PID ОС может сделать снимок неоднозначным. Не использовать снимок для принудительного завершения.
  3. Контракт владения внешними MCP с Claude/Codex: переиспользование и закрытие только своих серверов, без опасной очистки процессов по имени.
  4. Нативные графические панели/события там, где у харнеса есть поддерживаемый API; текущая реализация — меню и инструкции.
  5. Живые пользовательские испытания на Windows с Claude/VS Code и Codex. Автоматический CI не доказывает отсутствие всех утечек в сторонних программах.

Проверки#

Тесты покрывают окружение Windows и caller env, явное согласие/изменённый digest/повтор предложения, запрос остановки и освобождение слота, неизвестный счёт, ограниченные измерения ресурсов и снятие обработчиков сигналов. Терминальное меню проверено в реальном PTY: открытие → настройки → изменение числа вызовов → подтверждение → выход. Модель для этого не запускалась. Итог автоматической проверки смотри в CI соответствующего коммита; живые Claude/Codex и VS Code UI здесь не проверены.
