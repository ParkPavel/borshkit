Пространство и Git простыми словами#

Коротко: borshkit начать создаёт в корне проекта папку borshkit/. Это одновременно рабочее место Borshkit и хранилище Obsidian. История проекта её не видит, а у самой папки своя история — чтобы любое изменение можно было вернуть.

Что внутри#

команда
borshkit/
├── START-HERE.md     с чего начать — открой первым
├── STATUS.md         диспетчерская: кто работает, что ждёт тебя
├── journal.md        журнал простыми фразами
├── settings/         настройки (меняются только через предложения)
├── tasks/<задача>/   контракт, доказательства, логи, лист acceptance.md
├── knowledge/        карта проекта и твои заметки
├── materials/        сохранённые источники
├── questions/        вопросы к тебе (появляется с первым вопросом)
├── backups/          копии файлов перед «вернуть»
└── .state/           служебное: индекс SQL, блокировка

Как папка прячется от истории проекта#

При создании Borshkit дописывает в .gitignore правило /borshkit/ и сразу проверяет его командой git check-ignore. С флагом --только-локально правило пишется в .git/info/exclude, и .gitignore проекта не меняется. Если правило потом пропадёт, Borshkit откажется работать, пока его не вернут: иначе задачи и доказательства попали бы в историю проекта.

Проект без Git тоже подходит: тогда состояние считается по хешам файлов.

Своя история пространства#

У папки borshkit/ свой локальный репозиторий Git. Каждое важное действие (новая задача, приёмка, смена настроек) сохраняется как точка возврата с именем автора — человека или исполнителя. Сохранить вручную: borshkit сохранить "что изменилось".

Эта история никуда не отправляется. Нужна ли резервная копия — открытый вопрос: черновик обсуждения.

Git для новичка#

Команды отвечают на обычные вопросы, а не требуют знать Git:

Вопрос Команда
Что такое Git, в двух словах? borshkit история объяснить
Что было сделано? borshkit история
Что изменилось с последнего сохранения? borshkit что-изменилось
Кто менял этот файл? borshkit кто-что <файл>
Верни файл как было borshkit вернуть <файл> — сначала копия в backups/, потом возврат
Сохрани проект borshkit сохранить-проект "что изменилось" — с проверкой на ключи
Влей свежую основную версию в работу агента borshkit задача обновить <задача> — потом проверки и приёмка заново
Перенеси принятую работу агента borshkit собрать <задача> — только принятые задачи, только если они уже содержат текущую основную версию, только ты
Отправь на GitHub borshkit отправить — без перезаписи чужого, с проверкой на ключи всего, чего ещё нет на сервере, только ты

Добавь слово пространство, чтобы спросить про историю самой папки borshkit/: borshkit история пространство.

Чего Borshkit не делает никогда: reset --hard, принудительную отправку, удаление веток. При конфликте во время сборки он отменяет слияние и объясняет, что случилось.

Плагин Claude Code#

Плагин добавляет два хука и навык:

  • SessionStart напоминает агенту, где START-HERE и статус;
  • PreToolUse останавливает разрушающие команды Git, отправку и запись в настройки пространства.

Хуки срабатывают только в проектах, где есть пространство Borshkit. Это второй, советующий слой, а не песочница.
