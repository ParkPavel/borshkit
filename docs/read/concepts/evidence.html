Доказательства и устаревание#

Коротко: доказательство действует только для того состояния файлов, на котором его получили. Изменился хоть один байт — доказательство устарело, проверку надо повторить.

Зачем#

Модель пишет «готово, тесты проходят». Но тесты могли запускаться до последней правки. Или на другой ветке. Или не запускаться вовсе. Borshkit не верит словам — он хранит, на каком именно состоянии прошла проверка.

Как это работает#

  1. Перед проверкой Borshkit снимает слепок состояния:
    • в проекте с Git — текущий коммит (HEAD) и хеш SHA-256 каждого отслеживаемого и каждого нового, но не игнорируемого файла;
    • без Git — хеши всех файлов, кроме .git и папки пространства.
  2. Проверка запускается, её вывод сохраняется в журнал задачи.
  3. В доказательство записываются результат, слепок и хеши контракта, настроек, материалов задачи и кода самого Borshkit.
  4. При сверке (задача итог) Borshkit снимает слепок снова. Если он отличается — доказательство помечается как устаревшее и не засчитывается.
команда
состояние A ──проверка──► PASS (для A)
     │ правка файла
состояние B ──сверка──► доказательство для A устарело → «не проверено»

Несохранённая правка тоже меняет слепок: хеш считается по содержимому файла, а не по коммиту. В слепок входят и бит исполнения файла (кроме Windows, где его нет), и подмодули Git: их текущий коммит и несохранённые правки внутри.

Игнорируемые файлы (например, .env, node_modules/ и сама папка borshkit/) в слепок не входят. Если проверка зависит от них, их изменение доказательство не обесценит — такие вещи стоит закреплять в отслеживаемых файлах (например, lock-файлом зависимостей).

Что устаревает ещё#

Доказательство устаревает и тогда, когда изменились:

  • контракт задачи (цели, критерии, проверки);
  • настройки пространства;
  • материалы задачи;
  • код самого Borshkit (например, после обновления).

Лог проверки тоже защищён: если его правили после записи, доказательство не засчитывается. Если файлы менялись прямо во время проверки, её результат тоже не засчитывается.

Граница#

Доказательство показывает только то, что измеряет проверка. Если тесты не проверяют сохранение данных, PASS по тестам ничего не говорит о сохранении. Поэтому такие вещи становятся критериями model или manual — см. Приёмка.
