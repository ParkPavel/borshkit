Borshkit 0.14.0 — промежуточный выпуск#

Pre-release, 26 октября 2026. Первый этап перехода к работе в текущем Claude/Codex. Предназначен для пользовательского тестирования; стабильным latest остаётся 0.13.1. Это не завершённый системный диспетчер процессов.

Установить или обновить#

sh
npm install -g https://github.com/ParkPavel/borshkit/releases/download/0.14.0/borshkit.tgz
cd my-project
borshkit

Вместо my-project укажи свой проект. В терминале откроется меню; без TTY используй borshkit обзор --json. Публикации в реестре npm нет.

Для точного соответствия плагина архиву можно загрузить распакованную папку package как локальный плагин Claude Code (claude --plugin-dir <путь-к-package>). При использовании marketplace обнови плагин штатными средствами Claude и проверь версию 0.14.0. Команда входа — /borshkit:workspace.

Для Codex выполни в проекте borshkit начать, затем borshkit integration export --host codex. Если AGENTS.md уже содержит собственные инструкции, добавь ссылку на навык Borshkit вручную; автоматической перезаписи нет. Это экспорт инструкций, не отдельный плагин Codex.

Для VS Code скачай borshkit.vsix из релиза, установи через Extensions → Install from VSIX, открой «Borshkit: открыть рабочее пространство». VSIX и CLI имеют версию 0.14.0; публикации в Marketplace нет.

Что изменилось#

  • Текущий харнес выполняет работу собственными инструментами. Дополнительный агент, worktree и MCP не запускаются автоматически из обзора.
  • Терминальное меню и общий JSON-снимок: задачи, работы, вопросы, настройки, остановка, ресурсы. Реальный N/M для проверок; нет выдуманного процента работы модели.
  • Настройки через показанное предложение и явное согласие пользователя. Digest связывает применение с предложением; доверие к согласию остаётся на стороне харнеса.
  • Запрос остановки конкретной работы, heartbeat и регистрация PID; последовательная запись состояния. Потерянный владелец освобождает активный слот перед новым запуском, неизвестный счёт провайдера сохраняется.
  • RAM и накопленное время CPU измеряются по запросу. Обработчики сигналов принадлежащих команд снимаются после завершения; закрытие меню отменяет внешнюю проверку и не запускает следующие.
  • Исправлены caller env и регистр переменных Windows. Обычная отправка Git следует поручению пользователя и разрешениям харнеса; разрушительные операции блокируются.

Совместимость и откат#

Существующие пространства не сбрасываются и не получают новые лимиты автоматически. Новые пространства начинают с двух одновременных дополнительных вызовов и двух задач. Каталог исполнителей не ограничен этим числом. Старые явные команды дополнительных работ сохраняют изоляцию и worktree.

Перед тестированием сохрани копию своего пространства и незакоммиченные изменения. Откат CLI: установи архив 0.13.1 по инструкции стабильного выпуска; новые команды в нём отсутствуют. Изолированная реализация сохранена в server/isolated-runtime.

Проверки и оставшиеся ограничения#

Автоматические тесты используют временные проекты и поддельных исполнителей. CI проверяет Linux, Windows и macOS; release workflow дополнительно устанавливает точный tgz и проверяет VSIX. Сведения о сборке, checksum и smoke-результат приложены к релизу. Меню проверено в настоящем PTY. Живые Claude/Codex, VS Code с аккаунтами и пользовательская Windows-машина здесь не проверялись.

Нет Windows Job Objects, гарантированной очистки дерева после аварийного уничтожения родителя, жёстких лимитов CPU/RAM и управления внешними MCP. Измеряется зарегистрированный корневой PID, не всё дерево; PID может быть повторно использован ОС. STOP_REQUESTED не означает STOPPED. Учёт токенов/USD не резервирует RAM. Не завершай все процессы node/MCP по имени.
