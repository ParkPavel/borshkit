# Ответ на независимый аудит 0.10.1

Аудит от 2026-10-07 проверял коммит `ed89f16` (0.10.1) и нашёл 13 проблем (F2–F14) в достоверности приёмки, приватности и надёжности. Ни одна не опровергнута. Все исправлены в 0.11.0. Для каждой есть тест в [`test/audit.test.mjs`](../../test/audit.test.mjs), который падает на `ed89f16` и проходит после исправления. Тест F5 — в `test/plugin.test.mjs`.

## Что было и что стало

| ID | Было | Стало |
|---|---|---|
| F2 | Ревью привязывалось к состоянию на момент **записи** ответа | Работа снимает состояние, когда ревьюер **начинает**. Если файлы изменились до ответа, ревью устарело сразу (`freshness: STALE`) |
| F3 | `собрать` проверяло приёмку копии, но сливало её с основной версией, которую никто не проверял | `собрать` отказывает, если копия не содержит текущую основную версию или в ней есть несохранённые правки. Новая команда `задача обновить` вливает основную версию в копию; доказательства устаревают, приёмка проходит на объединённом состоянии |
| F4 | Ревью без семейства моделей при цели доверия закрывало критерий | Импортированное ревью (`задача отзыв`) помечено `imported` и само ничего не принимает. Ревью неизвестного семейства ждёт человека. Доверие действует только для измеренного семейства |
| F5 | Несколько PASS перед одним ответом человека считались несколькими случаями; состояния и модели не различались; решение по наблюдаемой доле | Один случай — один ответ человека в паре с последним PASS на той же работе (те же файлы, контракт, материалы), из работы-ревью. Учёт по семействам. Решение по верхней границе 95-процентного интервала Уилсона: 0 ошибок из 20 — это всё ещё до 16 % |
| F6 | Снимок не видел бит исполнения и подмодули | В снимке бит исполнения (кроме Windows) и коммит подмодуля с его несохранёнными правками |
| F7 | README обещал «ключи и персональные данные не уходят наружу» | Формулировки исправлены на шести языках и в SECURITY: Borshkit проверяет задание, которое отправляет сам; что агент читает из файлов копии, он не видит; проверки задач идут с полным окружением |
| F8 | Записи API-исполнителя проверялись только на «внутри копии»; без Git изоляции и проверки границ не было | Записи проверяются по `paths` до записи, всё или ничего; `.git` и папка пространства запрещены. Без Git пишущие роли — только с `--в-папке` и подтверждением человека; границы проверяются по хешам файлов с момента создания задачи |
| F9 | Частичные правки упавшего исполнителя уходили в коммит следующего, а его семейство не считалось автором | Упавший писатель получает свой коммит «Незавершённая работа …» и запись в `authors.json` (`partial: true`); ревьюер его семейства больше не «независим» |
| F10 | Урок задачи с границами `"."` никогда не устаревал | Такой урок привязан к снимку всего проекта (`bk-scope: project`). Ограничение карты (JS/TS и Markdown) описано в документации |
| F11 | Оценка сравнивала старый итог с текущими файлами | Задача с изменившимися файлами помечается «не сравнимо» и не входит в счёт ложных PASS |
| F12 | Отправка проверяла на ключи только коммиты после upstream, даже если upstream — другой remote | Проверяется всё, чего нет ни в одной ветке выбранного remote (`HEAD --not --remotes=<remote>`) |
| F13 | Два писателя одной задачи могли работать одновременно; сохранения истории пространства конкурировали | Блокировка писателя на задачу (с перехватом блокировки от завершившегося процесса); сохранения истории идут по очереди |
| F14 | Ответ CLI принимался даже при ненулевом коде завершения | Это сбой; ответ сохраняется в `tasks/<задача>/unconfirmed/` для человека |

## Что приёмка гарантирует теперь

- **Кодом:** критерии `auto` решают только проверки на том же состоянии; ревью относится к состоянию, которое видел ревьюер; в основную версию попадает ровно принятое дерево файлов; не проверенное не становится PASS.
- **Качеством критериев:** проверка доказывает только то, что измеряет.
- **Доверием, которое ты задал:** PASS модели закрывает критерий сам, только если ты так решил для метки и семейства и измерение это подтверждает с запасом на случайность.

## Что остаётся неизвестным

- Поведение настоящих Claude Code и Codex (коды завершения, что они читают) — нужен живой прогон с закреплёнными версиями.
- Работа на macOS.
- Выигрыш Borshkit по сравнению с работой напрямую через CLI с `AGENTS.md` и навыками. Ответ даст сравнение по [спецификации, §17](../spec.md): ложные PASS, вмешательства, время, расход на одинаковых задачах.
- Карта знаний для языков кроме JS/TS.
