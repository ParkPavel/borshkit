# Приёмка по целям

**Коротко:** ты задаёшь цели и критерии. Что можно проверить автоматически, Borshkit проверяет сам. Остальное превращается в короткий список «что посмотреть тебе». Итог — лист приёмки.

## Три класса критериев

| Класс | Кто решает | Пример |
|---|---|---|
| `auto` | проверка: тесты, сборка, линтер или встроенная проверка Borshkit | «Сборка и тесты проходят» |
| `model` | модель-ревьюер, но с ограничениями (ниже) | «Переключатель подписан и доступен с клавиатуры» |
| `manual` | ты | «После перезапуска тема осталась тёмной» |

### `auto`

Критерий выполнен, когда **все** его проверки дали PASS на текущем состоянии. Хотя бы один FAIL — критерий не выполнен. Проверка не запускалась или устарела — «не проверено».

Встроенные проверки Borshkit:
- `citations` — цитаты в отчёте исследования есть в сохранённых источниках, дословно ([Исследования](research.md));
- `attribution` — у каждого чужого источника есть благодарность, лицензия и ссылка;
- `readme-assets` — картинки README на месте, с подписями (alt) и не слишком тяжёлые.

### `model`

Модель-ревьюер отвечает PASS, FAIL или UNKNOWN и должна указать доказательство: файл и строку или команду.

- **FAIL** возвращает задачу на исправление.
- **PASS** закрывает критерий сам, только если для его метки (`tag`) есть твоя **цель доверия** и она подтверждена измерением. Например: «для `ui-a11y` модель ошибается с PASS не чаще 5 % случаев», и это показано на 20+ прогонах (`borshkit оценка доверие`).
- Без такой цели PASS модели — это пункт листа «посмотри сам».
- Ревью от **того же семейства моделей**, что и автор, независимым не считается: пункт ждёт тебя.

### `manual`

Слепая зона: автоматически не проверить. В контракте ты описываешь шаги, что должно быть видно и где смотреть. В листе это превращается в инструкцию. Ответ даёшь командой:

```sh
borshkit задача подтвердить тема C3 да "видел тёмную тему после перезапуска"
```

## Итог задачи

| Статус | Что значит |
|---|---|
| 🟢 **принято** | все цели достигнуты, состояние не менялось во время сверки |
| 🟡 **автоматически ок, ждёт тебя** | всё, что можно, доказано; остались пункты для человека |
| 🔴 **нужно исправить** | есть FAIL или правки вне границ задачи |
| ⚪ **не проверено** | для части критериев нет действующих доказательств |

Политика приёмки в контракте:
- `mixed` (по умолчанию) — принято, когда достигнуты все цели;
- `auto` — то же, но Borshkit предупредит, если есть критерии, которые не проверить автоматически;
- `manual` — даже при достигнутых целях итог подтверждаешь ты: `borshkit задача принять <задача>`.

## Границы задачи

В контракте есть `paths` — какие файлы задача может менять. Если работа изменила что-то за этими границами, итог — 🔴, и в листе видно, какие файлы. Файлы, изменённые ещё до начала задачи, не считаются.
