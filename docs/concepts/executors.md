# Исполнители, пулы и автопилот

**Коротко:** исполнитель — это тот, кто делает работу. Пул — очередь исполнителей на случай лимитов. Автопилот отвечает за тебя на рутинные вопросы, но никогда — на критические. Диспетчерская показывает, кто чем занят.

## Исполнители

| Вид (`kind`) | Что это | Как добавить |
|---|---|---|
| `claude-cli` | Claude Code по твоей подписке | `borshkit исполнитель добавить claude` |
| `codex-cli` | Codex CLI по подписке; умеет картинки через GPT Image | `borshkit исполнитель добавить codex` |
| `gemini-cli` | Gemini CLI без инструментов: sandbox, запрещающая политика, точная модель | `borshkit исполнитель добавить gemini` |
| `gemini-api` | Gemini API: текст, JSON и картинки PNG | манифест: `--файл манифест.json` |
| `openai-compat` | любой API в формате OpenAI: бесплатные, платные, локальные (Ollama, LM Studio) | манифест: `--файл манифест.json` |
| `command` | своя программа, которая читает задание и пишет ответ | манифест |

Добавление — это предложение настроек, его подтверждаешь ты в терминале. Ключи API в настройках не хранятся: там только **имя** переменной окружения.

`borshkit исполнитель проверить <имя>` сверяет, что программа установлена и понимает нужные флаги, а API отдаёт нужную модель. Результат сохраняется и показывается в `borshkit исполнители`.

У каждого исполнителя есть **политика данных**: `local` (на твоей машине), `no-train` (не обучается на данных), `trains`, `unknown`. В строгом режиме приватности работают только `local` и `no-train`.

## Пулы

Пул — упорядоченный список исполнителей в настройках:

```json
"pools": { "код": { "members": ["claude", "codex", "groq-free"], "maxSwitches": 3 } }
```

Работа идёт к первому, кто:
- разрешён режимом приватности;
- умеет то, что нужно роли (например, писать код или делать картинки);
- не из того же семейства моделей, что автор, — если роль это требует (ревьюер).

Если исполнитель упёрся в лимит, нет связи, нужен вход или он молчит, работа переходит к следующему. В журнале работы видна вся цепочка: «claude — лимит исчерпан → codex — ок». Если пишущий исполнитель успел что-то изменить, его правки сохраняются отдельным коммитом «Незавершённая работа …», а его семейство моделей записывается в авторы задачи.

Программа, которая выдала ответ, но завершилась с ошибкой, считается сбоем. Её ответ сохраняется в папке задачи (`unconfirmed/`) — посмотреть его можешь ты.

В проекте без Git отдельной копии нет. Пишущие роли там запускаются только с флагом `--в-папке` и твоим подтверждением в терминале.

## Отдельная копия проекта

В одной копии задачи одновременно работает только одна пишущая роль: вторая получит отказ, пока первая не закончит.

Роли, которые пишут файлы, работают не в твоей папке, а в копии на ветке `borshkit/<задача>` (git worktree рядом с проектом, в `../<проект>.borshkit-worktrees/`). Игнорируемых файлов, включая `.env`, там нет. Каждое сохранение подписано именем исполнителя. В основную версию работу переносит `borshkit собрать <задача>` — только после приёмки и только по твоему подтверждению.

## Вопросы, автопилот, критическая остановка

Иногда работе нужен ответ человека. Вопросы бывают двух видов:

| Вид | Пример | Кто отвечает |
|---|---|---|
| **рутинный** | «Исполнитель молчит 60 секунд. Ждать или передать следующему?» | ты; в автопилоте — ответ по умолчанию через `silenceSeconds` (60 с) |
| **критический** | пул исчерпан; собрать или отправить работу; ослабить защиту | только ты, в терминале |

При критическом вопросе Borshkit **останавливается правильно**:
1. сохраняет точку возврата в истории пространства;
2. пишет `stop-report.md` — что случилось и какие есть варианты;
3. пишет `handoff.md` и `handoff.json` — контекст для следующего исполнителя;
4. ставит работе статус «ждёт тебя».

Продолжить: `borshkit вопрос ответить <номер> <вариант>`, затем `borshkit работа продолжить <работа>`. Новый исполнитель получит передачу.

Автопилот включается в настройках (`"autopilot": true`) через предложение и твоё подтверждение. Звуки и уведомления — у твоего основного CLI.

## Диспетчерская

- `borshkit статус --следить` — живая картина: кому ушло, кто работает, что ждёт тебя;
- `borshkit/STATUS.md` и `borshkit/status.html` — то же в файлах, для Obsidian и браузера;
- `borshkit статус --строка` — короткая строка для строки статуса Claude Code.
