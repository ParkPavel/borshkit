# Сайт и документация как единый продукт

[Документация](https://parkpavel.github.io/borshkit/read/index.html) читается прямо на сайте: разделы, поиск по текстам, оглавление статьи, якорные ссылки, копирование кода и переход к следующей статье. Исходник на GitHub — отдельный необязательный переход. Все обычные ссылки между документами остаются на сайте.

## Один источник текста

Статьи лежат в Markdown: `docs/`, корневые README и служебные документы, `library/README.md`. Сборщик `scripts/site.mjs` создаёт HTML в `docs/read/`, индекс локального поиска и копирует публичные изображения в `docs/media/`. Эти каталоги не редактируют вручную. В Markdown сохраняются frontmatter и обычные относительные ссылки; на сайте они превращаются в адреса опубликованных статей. Ссылки на код ведут на GitHub явно.

```sh
npm run site
npm run site:check
```

`npm run verify` проверяет актуальность HTML относительно Markdown и картинок на Linux, Windows и macOS. Изменение статьи без пересборки не проходит проверку. Сборщик использует зафиксированный Marked 15.0.12 под MIT только при сборке: runtime-зависимостей CLI не добавлено. Произвольный HTML не переносится в страницы; поддерживается ограниченный набор безопасных тегов, небезопасные схемы ссылок блокируются.

## Что работает без JavaScript

Статьи, ссылки, боковая навигация, раскрывающиеся разделы и оглавление отдаются готовым HTML. JavaScript добавляет поиск, копирование, подсветку оглавления и мобильную кнопку разделов. В случае отказа clipboard код выделяется для ручного копирования. Поиск использует локальный JSON-индекс, не передаёт запросы внешнему сервису. Архивные Mermaid-графы доступны как раскрываемое текстовое описание; основные схемы процесса показываются готовыми SVG из проекта.

## README на GitHub

GitHub не выполняет JavaScript README и удаляет произвольные стили. Поэтому упаковка использует баннер, изображения-кнопки со ссылками, таблицу быстрых маршрутов, нативные details/summary и заметную плашку поддержки. Полная интерактивность находится на сайте. Баннер — иллюстрация рабочего цикла, а не обещание существующего графического приложения.

## Публикация

GitHub Pages читает main, каталог /docs. Сохрани сгенерированные страницы в PR; после проверок и слияния Pages публикует их вместе с сайтом. Для проверки адаптивности нужны реальные скриншоты и действия в браузере, а не только успешная генерация HTML.
