# Мастер настройки команды

После выбора среды продолжи по [операционному руководству](team-operations.md): оценки моделей, защищённое подтверждение, бюджет и явный монитор. Gemini доступен как preset `gemini`; API подключается манифестом.

После `borshkit начать` пространство содержит `SETUP.md`: среда, безопасность, модели, обязанности, предложение и готовность к работе. Мастер сохраняет выбор в `settings/setup.json`. Настройки проекта меняются только через отдельное применение предложения. Автопилот мастер не включает.

## Через приложение, в том числе с телефона

Попроси Codex или Claude выполнить шаги в проекте с пространством Borshkit. Для выбора и создания предложения TTY не требуется:

```sh
borshkit мастер
borshkit мастер вход codex-app
borshkit мастер безопасность строгий
borshkit мастер среда codex --модель <точный-id-модели> --данные no-train
borshkit мастер среда claude --модель <точный-id-модели> --данные no-train
borshkit мастер роли architect,implementer,tester,reviewer
borshkit мастер предложить
```

Указывай реальную модель и политику своего аккаунта. `no-train` — заявление об условиях аккаунта, не вывод мастера. Неизвестная политика блокирует кандидата в строгом режиме. Мастер не проверяет модель платным вызовом, не выполняет вход и не устанавливает программы. Найденный файл CLI в PATH означает только наличие файла на машине исполнения.

Выбор среды обозначает основной канал общения. Он не устанавливает расширения IDE и не создаёт нативный адаптер для Gemini или приложения. Голос в текст преобразует основная среда; аудио Borshkit не хранит.

Для API и дополнительных исполнителей используется существующий формат манифеста:

```sh
borshkit мастер среда groq --файл executor.json
```

Ключи передаются только через переменные окружения. Их значения не кладутся ни в манифест, ни в выбор мастера.

## Диалог в терминале

```sh
borshkit мастер --диалог
```

Мастер последовательно спрашивает среду, режим безопасности, Claude/Codex, точные модели, политику данных и роли. Завершённые шаги сохраняются: можно выйти и продолжить. По окончании он показывает итог и предлагает сохранить предложение. Применение настроек остаётся отдельной командой.

`borshkit начать --мастер` запускает диалог при наличии терминала. Из приложения он выводит все шаги без ожидания ввода. `--json` даёт структурированный отчёт; с диалогом этот флаг не используется.

## От выбора до готовой команды

| Факт | Чем подтверждается |
|---|---|
| Выбрано | локальный выбор среды, безопасности, моделей и ролей |
| Предложено | предложение pNNN, изменения и предупреждения |
| Применено | отдельная команда настроек; время применения |
| Подключение проверено | актуальная проба именно выбранной конфигурации |
| Оценена роль | отдельный материал оценки модели, инструкции и схемы |
| Назначено | план для задачи и применённые квалифицированные пулы |
| Запущено | свидетельство запуска конфигурации в истории попыток |
| Принято | проверки и приёмка конкретной задачи |

Проверка совместимости показывает требования выходных данных, записи файлов и приватности; она не измеряет качество модели. Если у пишущей роли и ревью есть только одно семейство, мастер предупреждает о невозможности независимого полного цикла. Полный резерв с учётом всех авторов и fallback создаётся позднее командой `команда план` для конкретной задачи.

После применения проверь подключения, оформи оценки ролей и сведения ресурсов по [справке](../reference/team-resources.md). Затем создай задачу с критериями, рассчитай и примени предложение команды; каждую роль запусти отдельно. Мастер не создаёт пулы из непроверенных кандидатов и не запускает пробную задачу сам.

Добавление исполнителей считается ослаблением защиты и требует подтверждения владельца: терминальной фразой либо passkey после доверенного сопряжения. `--да`, JSON и выбор среды этого не обходят. Подключение телефона и первоначальное сопряжение описаны в [операционном руководстве](team-operations.md).

## Изменения и продолжение

Изменение выбора делает старое предложение устаревшим. Изменение настроек после начала мастера требует нового подбора:

```sh
borshkit мастер заново
```

Эта команда очищает только выбор мастера, сохраняя действующие настройки, исполнителей и историю работ. Предложение также связано с инструкциями выбранных ролей и действует сутки. Применённое предложение остаётся историческим фактом; текущие настройки и реальные запуски показаны отдельно.

Автоматическая живая оценка ролей, бюджеты и пробная задача остаются следующей частью onboarding. Мастер не заявляет, что команда прошла эти проверки.
