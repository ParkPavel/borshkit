# Одна рабочая среда: Claude, Codex и терминал

**Промежуточный выпуск 0.14.0 (Pre-release).** Установи архив по [инструкции выпуска](../release-0.14.0.md). CLI и плагин должны быть из одной версии.

Borshkit хранит задачи, контекст и доказательства. Работу выполняет уже открытый Claude или Codex своими инструментами. Подключать ещё одну модель, запускать MCP-сервер или создавать отдельную копию проекта для этого не нужно. Приоритетный терминальный сценарий — Claude Code в VS Code; команды используют Node.js 22+ и рассчитаны на Windows, macOS и Linux.

## Вход

- **Claude Code:** после установки плагина открой `/borshkit:workspace`. Опиши цель обычными словами; помощник показывает задачу, этап, последнее событие и следующий шаг. `/borshkit:setup` помогает настроить выбранные возможности.
- **Codex:** в проекте создай пространство командой `borshkit начать`, затем выполни `borshkit integration export --host codex`. Экспорт добавляет инструкции в AGENTS.md; существующие собственные инструкции не перезаписываются. Попроси Codex открыть обзор Borshkit. Это инструкции для текущего агента, не отдельный плагин Codex.
- **Терминал, в том числе VS Code:** `borshkit` или `borshkit обзор` открывает меню. При первом входе предлагается создать пространство. Без TTY команда не заводит интерактивный цикл; `borshkit обзор --json` возвращает снимок состояния.
- **Расширение VS Code 0.14.0:** команда «Borshkit: открыть рабочее пространство» открывает то же меню в интегрированном терминале.

Меню: новая задача → проверить задачу → остановить работу → настройки → RAM и CPU → обновить. Для выбора достаточно номера. Имя задачи создаётся автоматически; человек вводит понятную цель. Чтобы проверка имела смысл, сначала согласуй критерии с текущим агентом. Прогресс N/M показывается для реально выполненных проверок; процента «размышления модели» нет.

## Настройки без кодовых фраз

В меню открой «Настройки», выбери изменение, посмотри разницу и нажми «Применить» или «Отмена». Можно выбрать ожидающее предложение, подготовленное агентом. Нет обязательной фразы «да, ослабить».

В Claude/Codex агент сначала получает `borshkit обзор review-settings <id> --json`, показывает изменения и последствия, затем запрашивает явное согласие средствами основного интерфейса. После согласия вызывает:

```sh
borshkit обзор apply-settings <id> --host claude --digest <digest> --decision apply --json
```

Для Codex используй `--host codex`. Digest связывает применение с показанной версией предложения; закрытое или изменённое предложение не применяется повторно. Это **заявленное согласие, доверенное основной среде**, а не криптографическое доказательство нажатия человеком. Borshkit не может проверить честность агента вне разрешений харнеса. Не передавай агенту право подтверждать за тебя. Изолированный вариант сохранён в ветке [server/isolated-runtime](https://github.com/ParkPavel/borshkit/tree/server/isolated-runtime).

## Дополнительные исполнители и процессы

Обычный `git push` следует поручению пользователя и разрешениям основного харнеса; принудительная отправка и разрушительные команды остаются запрещены защитным hook.

Текущий агент не требует регистрации. Каталог дополнительных исполнителей не ограничен количеством; роли описывают специализацию отдельных вызовов. Дополнительный запуск остаётся отдельным явным действием. Совместимые CLI/API можно подключить через существующие манифесты. Это не обещание поддержки любого агентного протокола.

Новые пространства допускают до двух одновременных дополнительных вызовов и двух задач. Предел регулируется в настройках; существующие пространства сохраняют свои значения. Этот предел не ограничивает процессы, запущенные самим Claude/Codex вне Borshkit.

`borshkit обзор stop <id> --json` передаёт запрос владельцу работы. **STOP_REQUESTED ещё не STOPPED.** Владелец останавливает свой вызов и освобождает активный слот. Для старых работ без токена владения используй терминал, где они были запущены. Потерянный владелец и устаревший heartbeat не считаются достоверной продолжающейся работой.

`borshkit обзор --json --resources` измеряет зарегистрированные активные процессы по запросу. RAM — наблюдаемая резидентная память, CPU — накопленное время процессора, не процент загрузки. Это не монитор всех дочерних процессов и не жёсткий лимит ОС. После завершения ОС освобождает адресное пространство процесса; оставшиеся дочерние процессы могут продолжать расходовать ресурсы. Учёт токенов и USD — отдельный механизм, он не резервирует RAM. Неизвестный счёт провайдера сохраняется даже после освобождения слота выполнения.

## Честные ограничения

Фонового сервера, наблюдателя и автоматического запуска MCP у обзора нет. Ctrl+C/SIGTERM/SIGHUP передаются принадлежащим Borshkit командам; ожидание остановки ограничено. При аварийном уничтожении родителя или отказе ОС полная очистка дерева не гарантирована. Windows Job Objects и постоянный надзор всего дерева пока не реализованы.

Borshkit не завершает процессы по имени `node`, `claude` или `mcp`: это может уничтожить чужую работу. MCP-серверы, запущенные Claude/Codex, управляются их владельцем. Нативные панели, кнопки и настройки в чатах зависят от возможностей и версии харнеса; здесь реализованы команды и инструкции, а не новый графический интерфейс Claude/Codex. Живые испытания этих интерфейсов ожидаются от пользователей.
