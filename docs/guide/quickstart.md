# Быстрый старт: первая задача

Здесь ты создашь пространство, опишешь задачу, поручишь её агенту и получишь лист приёмки. Нужны Node.js 22+ и Git. Для создания задач и локальных проверок модель не нужна. Пример работы агентов ниже использует два отдельно установленных и авторизованных исполнителя: Claude Code пишет, Codex проверяет. Подписка или API-оплата зависит от выбранной среды.

## 1. Установить

Основной путь — готовый архив [релиза 0.13.0](https://github.com/ParkPavel/borshkit/releases/tag/0.13.0):

```sh
npm install -g https://github.com/ParkPavel/borshkit/releases/download/0.13.0/borshkit.tgz
borshkit помощь
```

Реестр npm пока не используется: npm устанавливает архив напрямую из GitHub.

Дополнительно, для Claude Code:

```
/plugin marketplace add ParkPavel/borshkit
/plugin install borshkit@borshkit
```

Плагин добавляет навык, slash-команды и защитные hooks, но не глобальную CLI в PATH. Установи CLI командой выше. Клонирование нужно только для работы с исходниками:

```sh
git clone https://github.com/ParkPavel/borshkit.git
cd borshkit && npm link
```

Проверить: `borshkit помощь`.

## 2. Создать пространство

```sh
cd my-project
borshkit начать
```

Замени `my-project` на путь своего проекта. Для описанного ниже запуска агента в отдельной копии нужен Git-проект хотя бы с одним коммитом; проверить состояние можно командой `git status`. Не создавай пространство внутри установленного пакета Borshkit.

В корне появится папка `borshkit/`, а в `.gitignore` — правило, которое прячет её от истории проекта. Открой `borshkit/START-HERE.md`: там то же самое, что здесь, но короче.

## 3. Выбрать команду

Проще всего — в Claude Code командой плагина:

```
/borshkit:setup
```

Claude задаст вопросы с готовыми вариантами, сам выполнит шаги мастера и в конце даст одну команду, которую ты запустишь в своём терминале. Ключи API в чат не пишутся: ты кладёшь их в переменные окружения сам.

То же самое вручную:

```sh
borshkit мастер
```

Выбери среду, безопасность, точные модели и роли по [руководству мастера](setup.md). В терминале доступен `--диалог`, через приложение — пошаговые команды. После создания предложения настройки применяются отдельно. Для полного распределения ролей нужны актуальные оценки, проверка подключения и независимое семейство ревью.

### Добавить исполнителя напрямую

```sh
borshkit исполнитель добавить claude
borshkit исполнитель добавить codex
```

Borshkit покажет, что изменится, и попросит подтвердить вводом фразы. Затем сам проверит, что программа установлена и понимает нужные флаги.

API подключаются так же, адрес и имя переменной с ключом уже заданы:

```sh
borshkit исполнитель добавить freellmapi                        # свой сервер бесплатных лимитов
borshkit исполнитель добавить ollama --модель qwen3:8b           # модели на твоём компьютере
borshkit исполнитель добавить groq --модель <id> --семейство meta
```

Политика данных пока «неизвестна». Если ты знаешь, что провайдер не обучается на твоих данных, укажи это: `--данные no-train`. Это важно для строгого режима приватности.

## 4. Описать задачу

```sh
borshkit задача новая dark-mode --цель "Тёмная тема в настройках, выбор сохраняется после перезапуска"
```

Команда создаёт **черновик**, а не готовую к запуску задачу. Заполни `paths`, `goals`, `criteria` и `checks`; сохрани созданные `taskId` и `base`. Образец ниже нельзя целиком копировать поверх контракта: у него другая задача и демонстрационная база.

Цели и критерии можно написать самому в `borshkit/tasks/dark-mode/contract.json` (образец — [`examples/contract.json`](../../examples/contract.json)) или поручить архитектору:

```sh
borshkit работа запустить dark-mode --роль architect --исполнитель claude
```

Архитектор сохраняет предложение в `borshkit/tasks/dark-mode/architect-proposal.json`. Прочитай его и перенеси согласованные `paths`, `goals`, `criteria` и `checks` в `contract.json`. Затем:

```sh
borshkit задача анализ dark-mode
```

`задача анализ` покажет размытые критерии и то, что автоматически проверить нельзя. Это пункты, которые потом посмотришь ты.

Имена задач: латинские буквы, цифры, `-` и `_`. Цель и критерии можно писать по-русски.

Чтобы начать от сохранённой версии: `borshkit задача новая release-fix --цель "Исправить выпуск" --база 0.12.0`. База должна существовать в локальном Git; рабочая копия начнётся с этого коммита, без несохранённых изменений проекта.

## 5. Поручить работу

```sh
borshkit работа запустить dark-mode --роль implementer --исполнитель claude --линза full
```

Разработчик работает в отдельной копии проекта на ветке `borshkit/dark-mode`. Твоя папка не меняется. Следить: `borshkit статус --следить`.

Для интерфейса бери `ui-engineer`: у него есть навыки по анимации, отступам и доступности.

## 6. Проверить

```sh
borshkit задача проверить dark-mode                                   # тесты, сборка, линтер в копии задачи
borshkit работа запустить dark-mode --роль reviewer --исполнитель codex   # ревью от другой семьи моделей
borshkit задача итог dark-mode
```

`задача итог` пишет лист приёмки `borshkit/tasks/dark-mode/acceptance.md`:
- ✅ что доказано проверками;
- ❌ что нужно исправить;
- 🟡 что посмотреть тебе — с шагами;
- ⚪ что не проверено.

## 7. Ответить по ручным пунктам

```sh
borshkit задача подтвердить dark-mode C3 да "видел тёмную тему после перезапуска"
borshkit задача итог dark-mode
```

Когда итог — 🟢 **принято**, перенеси работу в основную версию и отправь:

```sh
borshkit собрать dark-mode
borshkit отправить
```

Обе команды требуют явного подтверждения человека в терминале. Не поручай агенту подтверждать эти действия от твоего имени.

Если за время задачи основная версия проекта изменилась, `собрать` откажет и попросит сначала `borshkit задача обновить dark-mode`. Основная версия вольётся в копию задачи, и проверки с приёмкой пройдут заново — на том, что действительно попадёт в проект.

## Если что-то пошло не так

| Что видишь | Что делать |
|---|---|
| «Исполнитель молчит…» | ответь на вопрос: `borshkit вопросы`, затем `borshkit вопрос ответить <номер> <вариант>` |
| работа «ждёт тебя» | прочитай `stop-report.md` в папке задачи, ответь на вопрос, затем `borshkit работа продолжить <работа>` |
| доказательство «устарело» | файлы изменились после проверки — запусти `задача проверить` ещё раз |
| «Пространство занято другой командой» | дождись завершения процессов Borshkit. Удаляй `borshkit/.state/lock` только после проверки, что команда-владелец действительно завершена; иначе возможен конфликт записей |
| «Основная версия проекта изменилась после начала задачи» | `borshkit задача обновить <задача>`, затем `задача проверить` и `задача итог` |
| «Проект без Git: отдельной копии для агента нет» | добавь Git (`git init` и первое сохранение) или запусти работу с `--в-папке` |
| что-то непонятно в Git | `borshkit история объяснить` |
