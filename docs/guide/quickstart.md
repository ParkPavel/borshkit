# Быстрый старт: первая задача

Здесь ты создашь пространство, опишешь задачу, поручишь её агенту и получишь лист приёмки. Нужны Node.js 22+ и Git. Нужен хотя бы один исполнитель: Claude Code или Codex по подписке.

## 1. Установить

Как плагин Claude Code:

```
/plugin marketplace add ParkPavel/borshkit
/plugin install borshkit@borshkit
```

Плагин сам добавляет команды `borshkit` и `borsch` в терминал Claude Code. Чтобы пользоваться ими и в своём терминале, поставь команду:

```sh
git clone https://github.com/ParkPavel/borshkit.git
cd borshkit && npm link
```

Проверить: `borshkit помощь`.

## 2. Создать пространство

```sh
cd мой-проект
borshkit начать
```

В корне появится папка `borshkit/`, а в `.gitignore` — правило, которое прячет её от истории проекта. Открой `borshkit/START-HERE.md`: там то же самое, что здесь, но короче.

## 3. Выбрать команду

```sh
borshkit мастер
```

Выбери среду, безопасность, точные модели и роли по [руководству мастера](setup.md). В терминале доступен `--диалог`, через приложение — пошаговые команды. После создания предложения настройки применяются отдельно. Для полного распределения ролей нужны актуальные оценки, проверка подключения и независимое семейство ревью.

### Добавить исполнителя напрямую

```sh
borshkit исполнитель добавить claude
borshkit исполнитель добавить codex
```

Borshkit покажет, что изменится, и попросит подтвердить вводом фразы. Затем сам проверит, что программа установлена и понимает нужные флаги.

Политика данных пока «неизвестна». Если ты знаешь, что провайдер не обучается на твоих данных, укажи это: `--данные no-train`. Это важно для строгого режима приватности.

## 4. Описать задачу

```sh
borshkit задача новая тема --цель "Тёмная тема в настройках, выбор сохраняется после перезапуска"
```

Цели и критерии можно написать самому в `borshkit/tasks/тема/contract.json` (образец — [`examples/contract.json`](../../examples/contract.json)) или поручить архитектору:

```sh
borshkit работа запустить тема --роль architect --исполнитель claude
borshkit задача анализ тема
```

`задача анализ` покажет размытые критерии и то, что автоматически проверить нельзя. Это пункты, которые потом посмотришь ты.

## 5. Поручить работу

```sh
borshkit работа запустить тема --роль implementer --исполнитель claude --линза full
```

Разработчик работает в отдельной копии проекта на ветке `borshkit/тема`. Твоя папка не меняется. Следить: `borshkit статус --следить`.

Для интерфейса бери `ui-engineer`: у него есть навыки по анимации, отступам и доступности.

## 6. Проверить

```sh
borshkit задача проверить тема                                   # тесты, сборка, линтер в копии задачи
borshkit работа запустить тема --роль reviewer --исполнитель codex   # ревью от другой семьи моделей
borshkit задача итог тема
```

`задача итог` пишет лист приёмки `borshkit/tasks/тема/acceptance.md`:
- ✅ что доказано проверками;
- ❌ что нужно исправить;
- 🟡 что посмотреть тебе — с шагами;
- ⚪ что не проверено.

## 7. Ответить по ручным пунктам

```sh
borshkit задача подтвердить тема C3 да "видел тёмную тему после перезапуска"
borshkit задача итог тема
```

Когда итог — 🟢 **принято**, перенеси работу в основную версию и отправь:

```sh
borshkit собрать тема
borshkit отправить
```

Обе команды спросят подтверждение в терминале. Агент сделать это за тебя не может.

Если за время задачи основная версия проекта изменилась, `собрать` откажет и попросит сначала `borshkit задача обновить тема`. Основная версия вольётся в копию задачи, и проверки с приёмкой пройдут заново — на том, что действительно попадёт в проект.

## Если что-то пошло не так

| Что видишь | Что делать |
|---|---|
| «Исполнитель молчит…» | ответь на вопрос: `borshkit вопросы`, затем `borshkit вопрос ответить <номер> <вариант>` |
| работа «ждёт тебя» | прочитай `stop-report.md` в папке задачи, ответь на вопрос, затем `borshkit работа продолжить <работа>` |
| доказательство «устарело» | файлы изменились после проверки — запусти `задача проверить` ещё раз |
| «Пространство занято другой командой» | дождись её конца; если она точно завершена, удали `borshkit/.state/lock` |
| «Основная версия проекта изменилась после начала задачи» | `borshkit задача обновить <задача>`, затем `задача проверить` и `задача итог` |
| «Проект без Git: отдельной копии для агента нет» | добавь Git (`git init` и первое сохранение) или запусти работу с `--в-папке` |
| что-то непонятно в Git | `borshkit история объяснить` |
