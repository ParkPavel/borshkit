# Безопасность

## Как сообщить об уязвимости

Не публикуй уязвимость в открытом issue. Используй [приватное сообщение об уязвимости на GitHub](https://github.com/ParkPavel/borshkit/security/advisories/new) или напиши владельцу репозитория.

## От чего Borshkit защищает и где защита заканчивается

| Угроза | Защита | Граница |
|---|---|---|
| Ключи уходят к модели | пакет для исполнителя проверяется до отправки; дочерние процессы получают только разрешённые переменные окружения | поиск по шаблонам ловит не всё |
| Агент читает `.env` | пишущие роли работают в отдельной копии (git worktree), куда игнорируемые файлы не попадают | агент, запущенный прямо в корне проекта, видит всё, что разрешают его собственные права |
| Агент ослабляет защиту | настройки меняются только через предложения; ослабление — после ввода фразы в настоящем терминале; правка в обход замечается и останавливает запись | программа, которая управляет твоим терминалом, может ввести фразу за тебя |
| Потеря работы | нет `reset --hard`, принудительной отправки и удаления веток; «вернуть» сначала сохраняет копию | — |
| Ключ в истории проекта | `сохранить-проект` и `отправить` проверяют изменения на ключи | только известные форматы ключей |
| Ложное «готово» | приёмка по доказательствам, привязанным к состоянию; неизвестное — UNKNOWN | доказательство показывает только то, что измеряет проверка |
| Навык из чужого пакета влияет на работу | навыки подключаются только к своей роли или по флагу `--навыки`; чужие хуки не ставятся; текст пакета зафиксирован по версии и виден в репозитории | навык — это инструкция модели; что в нём написано, решает его автор |

Хуки Claude Code — второй, советующий слой, а не песочница.
