# Borshkit (Борщкит)

**Modular AI Workspace** — рабочее пространство для работы с AI-агентами над любым проектом: плагином, веб-приложением, библиотекой или исследованием. Ты описываешь цель, агенты работают, а Borshkit показывает, что **доказано** проверками, а что нужно посмотреть тебе самому.

> Статус: **0.2.0, ранняя разработка.**
> - Работает: ядро приёмки, локальное пространство, материалы и проверка цитат, режимы приватности, доверенный агент настройки.
> - Следующие этапы: исполнители-агенты, база знаний и диспетчерская ([план](docs/spec.md#16-этапы-и-критерии-готовности-без-сроков)).

## Главная идея

«Готово» от модели — это ещё не приёмка. Borshkit привязывает каждое доказательство к точному состоянию файлов. Если файлы изменились, отметка устаревает. Что можно проверить автоматически, проверяется автоматически. Что нельзя, превращается в короткую инструкцию для человека. А то, что не проверено, так и называется: **не проверено**.

## Быстрый старт

Нужны Node.js 22+ и Git. Зависимостей нет.

```sh
git clone https://github.com/ParkPavel/borshkit.git
cd путь/к/твоему/проекту
node путь/к/borshkit/bin/borshkit.mjs начать
```

`начать` создаёт в корне проекта папку `borshkit/`:
- это и пространство, и хранилище Obsidian;
- в `.gitignore` проекта автоматически добавляется правило, так что пространство не попадёт в историю проекта;
- у самой папки появляется своя локальная история — точки возврата, которые никогда не покидают компьютер.

Если трогать `.gitignore` нельзя, добавь `--только-локально`: правило будет записано в `.git/info/exclude`.

## Что уже работает

| Команда | Что делает |
|---|---|
| `borshkit начать` | создаёт пространство, прячет его от истории проекта, заводит историю пространства |
| `borshkit статус` | режим приватности, автопилот, задачи и что ждёт тебя |
| `borshkit доктор` | проверка окружения и пространства простыми словами |
| `borshkit сохранить "…"` | точка возврата в истории пространства |
| `borshkit задача новая <имя> --цель "…"` | новая задача с исходным снимком проекта |
| `borshkit задача анализ <имя>` | что в задаче нельзя будет проверить — ещё до начала работы |
| `borshkit задача проверить <имя>` | запускает автоматические проверки, логи привязаны к состоянию |
| `borshkit задача отзыв <имя> --результат r.json --исполнитель codex` | записывает ответ модели-ревьюера |
| `borshkit задача итог <имя>` | сверка по целям и лист приёмки `acceptance.md` |
| `borshkit задача подтвердить <имя> <критерий> да\|нет "…"` | твоё решение по пункту листа |
| `borshkit задача принять <имя>` | общая приёмка, когда её требует политика задачи |
| `borshkit материал добавить <файл> \| --url … \| --текст "…"` | сохраняет источник по содержимому; новая версия страницы — новая запись |
| `borshkit приватность [умеренный\|строгий\|эксперимент]` | ужесточить можно всегда, ослабить — только тебе в терминале |
| `borshkit настройки предложить \| применить \| принять \| вернуть` | настройки меняются через предложения; правка в обход останавливает записи |
| `borshkit эксперимент начать \| ключ \| завершить` | журнал имён ключей; сессия «грязная», пока ты не подтвердишь отзыв |

Английские имена тоже работают (`init`, `status`, `task verify` …), а `--json` даёт ответ для программ.

## Как принимается задача

Контракт задачи (`borshkit/tasks/<имя>/contract.json`, пример — [examples/contract.json](examples/contract.json)) состоит из **целей**, **критериев** и **проверок**. У каждого критерия свой класс:

| Класс | Кто решает | Итог |
|---|---|---|
| `auto` | проверка (тесты, сборка, линтер) | PASS или FAIL автоматически |
| `model` | модель-ревьюер | FAIL возвращает задачу на исправление. PASS решает сам, только если твоя цель доверия подтверждена измерением; иначе это пункт для тебя |
| `manual` | ты | пункт листа приёмки: что сделать, что должно быть видно, где смотреть |

Задача **принята**, когда достигнуты все её цели. Статусы:
- 🟢 **принято**;
- 🟡 **автоматически ок, ждёт тебя**;
- 🔴 **нужно исправить**;
- ⚪ **не проверено**.

## Исследования и источники

Источники вне Git — файлы, страницы, вставленный текст — хранятся копиями по содержимому. Задача перечисляет их в поле `materials`, а отчёт ссылается на них так: `(источник: m-0123456789ab, «точная цитата»)`. Встроенная проверка `citations` сверяет:
- объявлен ли источник в задаче и цела ли его копия;
- есть ли цитата в источнике дословно;
- нет ли в отчёте адресов, полученных в обход Borshkit.

Следует ли вывод из источника, решает модель-ревьюер или ты.

## Приватность и настройки

| Режим | Что можно отправлять наружу |
|---|---|
| **умеренный** (по умолчанию) | код и документы, но не ключи и не персональные данные |
| **строгий** | ничего без явного «да» |
| **эксперимент** | всё, но ключи должны быть одноразовыми; Borshkit записывает их имена и ждёт твоего подтверждения, что они отозваны |

- Настройки меняются только через предложения. Предлагать может доверенный агент или ты, а всё, что ослабляет защиту, подтверждаешь только ты в терминале.
- Если правка настроек сделана в обход Borshkit, любые записи останавливаются, пока ты её не примешь или не откатишь.
- Подтверждение в терминале — защита от случайностей, а не граница безопасности: агент, запущенный через инструмент, ответить за тебя не может, но злонамеренный процесс с доступом к твоему терминалу — может.
