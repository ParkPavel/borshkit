# Borshkit (Борщкит)

**Modular AI Workspace** — рабочее пространство для AI-агентов над любым проектом: плагином, веб-приложением, библиотекой или исследованием. Ты описываешь цель, агенты работают, а Borshkit показывает, что **доказано** проверками, а что нужно посмотреть тебе самому.

> Статус: **0.9.0 — весь стек собран, идёт проверка на реальных проектах.**
> - Работает: приёмка, пространство, приватность, исполнители и пулы, автопилот, диспетчерская, база знаний, роли, атрибуция, оболочка Git, плагин Claude Code, оценка.
> - Тесты используют поддельных исполнителей; что ещё не проверено вживую — в разделе [«Честно о границах»](#честно-о-границах).

## Главная идея

«Готово» от модели — это ещё не приёмка:
- Каждое доказательство привязано к точному состоянию файлов. Если файлы изменились, отметка устаревает.
- Что можно проверить автоматически, проверяется автоматически.
- Что нельзя, превращается в короткую инструкцию для человека.
- То, что не проверено, так и называется: **не проверено**.

## Установка

Нужны Node.js 22+ и Git. Зависимостей нет.

**Как плагин Claude Code** (hooks и skill):

```
/plugin marketplace add ParkPavel/borshkit
/plugin install borshkit@borshkit
```

**Командная строка:**

```sh
git clone https://github.com/ParkPavel/borshkit.git
cd borshkit && npm link        # команды borshkit и borsch
```

Пакет в npm пока не опубликован.

## Путь одной задачи

```sh
cd мой-проект
borshkit начать                                  # папка borshkit/ в корне, скрыта от истории проекта
borshkit исполнитель добавить claude             # подписочный CLI; подтверждаешь в терминале
borshkit задача новая тема --цель "Тёмная тема в настройках"
borshkit работа запустить тема --роль architect --исполнитель claude   # предложит цели и критерии
borshkit задача анализ тема                      # что нельзя будет проверить автоматически
borshkit работа запустить тема --роль implementer --исполнитель claude --линза full
borshkit задача проверить тема                   # тесты, сборка, линтер — в копии задачи
borshkit работа запустить тема --роль reviewer --исполнитель codex      # другое семейство моделей
borshkit задача итог тема                        # лист приёмки: что проверено, что ждёт тебя
borshkit задача подтвердить тема C3 да "видел тёмную тему после перезапуска"
borshkit собрать тема                            # принятая работа — в основную версию
borshkit отправить                               # на GitHub, без перезаписи чужого
```

Папка `borshkit/` — это и пространство, и хранилище **Obsidian**. В ней лежат:
- `START-HERE.md` — с чего начать;
- `STATUS.md` — диспетчерская;
- `knowledge/` — карта проекта;
- `tasks/` — листы приёмки;
- `journal.md` — журнал простыми фразами.

## Что умеет

| Область | Команды | Суть |
|---|---|---|
| Пространство | `начать`, `статус`, `доктор`, `сохранить` | своя локальная история, автоматический gitignore |
| Задачи и приёмка | `задача новая · анализ · проверить · отзыв · итог · подтвердить · принять` | цели, критерии `auto/model/manual`, лист приёмки |
| Исполнители | `исполнители`, `исполнитель добавить · проверить` | Claude Code, Codex, OpenAI-совместимые API, свои команды |
| Работы | `работа запустить · список · продолжить`, `роли` | 13 ролей, пулы, переключение при лимитах |
| Диспетчерская | `статус --следить`, `статус --строка`, `вопросы`, `вопрос ответить` | кому ушло, кто работает, что ждёт тебя |
| Знания | `знания собрать · sql · найти · контекст · урок · экспорт` | заметки с `[[связями]]` для Obsidian + SQL |
| Источники | `материал добавить · список · обновить` | файлы, страницы, текст, Jina, вывод инструментов Agent Reach |
| Приватность | `приватность`, `настройки …`, `эксперимент …` | три режима, доверенный агент, журнал ключей |
| Git | `история`, `что-изменилось`, `кто-что`, `вернуть`, `сохранить-проект`, `собрать`, `отправить` | простыми словами, ничего разрушающего |
| Атрибуция | `атрибуция проверить · картинки · контрибьюторы` | благодарности, лицензии, все контрибьюторы |
| Оценка | `оценка запустить · доверие` | ложные PASS, вмешательства, доверие к моделям |

Все команды есть и по-английски (`init`, `task verify` …). Флаг `--json` даёт ответ для программ. Полный список — `borshkit помощь`.

## Приёмка по целям

| Класс критерия | Кто решает | Итог |
|---|---|---|
| `auto` | проверка (тесты, сборка, линтер, `citations`, `attribution`, `readme-assets`) | PASS или FAIL автоматически |
| `model` | модель-ревьюер | FAIL возвращает задачу на исправление. PASS решает сам, только если твоя цель доверия подтверждена измерением (`оценка доверие`); иначе это пункт для тебя |
| `manual` | ты | пункт листа: что сделать, что должно быть видно, где смотреть |

Статусы задачи:
- 🟢 **принято**;
- 🟡 **автоматически ок, ждёт тебя**;
- 🔴 **нужно исправить**;
- ⚪ **не проверено**.

Ревью от того же семейства моделей, что и автор, независимым не считается.

## Исполнители, роли и автопилот

- **Исполнители** объявляются в настройках. Подписочные CLI добавляются одной командой, API и свои программы — манифестом. Проверка `исполнитель проверить` сверяет флаги CLI или список моделей API.
- **Пулы** — упорядоченные списки исполнителей. При лимите или молчании работа переходит к следующему, кто разрешён режимом приватности и умеет нужное. Каждая передача видна в диспетчерской.
- **Роли:** `architect`, `researcher`, `implementer` (с линзой «ленивый сеньор» из [Ponytail](https://github.com/DietrichGebert/ponytail)), `designer`, `reviewer`, `simplicity-reviewer`, `tester`, `adversarial-reviewer`, `flow-auditor`, `docs-writer`, `readme-designer` (изображения), `attribution-steward`, `configurator`. Пишущие роли работают в отдельной копии проекта (git worktree), а их сохранения подписаны именем исполнителя.
- **Автопилот** отвечает на рутинные вопросы ответом по умолчанию через 60 секунд. Например, исполнитель молчит: пока идёт инструмент — ждём, иначе — передаём следующему.
- **Критические вопросы** решает только человек в терминале. Это исчерпанный пул, сборка, отправка и ослабление защиты. Перед остановкой Borshkit сохраняет точку возврата и пишет `stop-report.md` и `handoff`; работа продолжается по номеру.
- **Строка статуса Claude Code:** добавь в `.claude/settings.json`:
  ```json
  { "statusLine": { "type": "command", "command": "borshkit статус --строка" } }
  ```

## Приватность

| Режим | Что можно отправлять наружу |
|---|---|
| **умеренный** (по умолчанию) | код и документы, но не ключи и не персональные данные |
| **строгий** | только исполнителям, которые не обучаются на данных, или локальным; интернет — после явного «да» |
| **эксперимент** | всё, но ключи одноразовые: Borshkit записывает их имена и ждёт подтверждения, что они отозваны |

- Пакет для исполнителя проверяется на ключи и персональные данные до отправки.
- Дочерние процессы получают только разрешённые переменные окружения.
- Пишущие агенты работают в копии, где нет игнорируемых файлов, в том числе `.env`.
- Настройки меняются только через предложения. Ослабление защиты подтверждаешь ты.
- Подтверждение в терминале защищает от случайностей и от агента, запущенного через инструмент. Это не граница безопасности.

## База знаний для людей и агентов

`borshkit знания собрать` превращает проект в связанную базу:
- заметки модулей, тестов и документов с типизированными связями (`imports`, `tested-by`, `documented-by`, `decided-in` …) в виде `[[wikilinks]]` — граф виден в Obsidian;
- SQL-индекс (`borshkit знания sql "SELECT …"`, только чтение);
- срез контекста для каждой работы.

Твои заметки Borshkit не трогает. Уроки из принятых задач устаревают сами, когда меняется код, о котором они.

## Исследования

- Источники хранятся копиями по содержимому. Добавить можно файл, `--url`, `--текст`, страницу через `--через jina` или вывод инструмента через `--команда "yt-dlp …"` (маршруты [Agent Reach](https://github.com/panniantong/agent-reach)).
- Отчёт ссылается на источники так: `(источник: m-0123456789ab, «точная цитата»)`.
- Проверка `citations` сверяет наличие источника, целость копии и дословность цитаты. Адреса, полученные в обход Borshkit, она отклоняет.

## Честно о границах

- Адаптеры Claude Code и Codex проверены на поддельных CLI с тем же форматом событий. Флаги установленного Claude Code 2.1.289 сверены. Живые запуски с настоящими моделями в CI не выполняются.
- Генерация изображений через Codex (GPT Image) не проверена — её подтверждает `исполнитель проверить` на твоей подписке. Изображения через OpenAI-совместимые API проверены на тестовом сервере.
- Видит ли граф Obsidian связи из свойств заметок, не проверено. Связи дублируются в тексте карты `index.md`.
- `node:sqlite` в Node 22 пока экспериментальный.
- Поиск персональных данных по шаблонам ловит не всё: почту, телефоны, номера карт.
