Проведи человека через настройку Borshkit в текущем проекте. Он может быть новичком: говори по-русски, простыми словами, по одному шагу. Вопросы задавай инструментом AskUserQuestion с готовыми вариантами, а не длинным текстом. Пожелание человека, если есть: $ARGUMENTS

## Правила

- Ключи API никогда не спрашивай в чате и не записывай в файлы. Человек сам кладёт ключ в переменную окружения в своём терминале. Если ключ всё же оказался в чате, скажи, что он теперь в истории переписки, и предложи выпустить новый ключ.
- Настройки меняются только командами `borshkit`. Не правь `borshkit/settings/` руками.
- Применение настроек, которое ослабляет защиту (например, добавляет исполнителя), подтверждает только человек в своём терминале. Не запускай `borshkit настройки применить` за него и не ищи обходных путей.
- Модель указывается точно. Если человек не знает её id, подскажи, где посмотреть (например, `/model` в Claude Code или список моделей на странице сервиса), но не выдумывай.
- Если команда вернула ошибку, перескажи её простыми словами и предложи, что сделать.

## Шаги

1. **Проверка.** Выполни `borshkit доктор`. Если команды `borshkit` нет, скажи, что нужен Node.js 22 или новее, и остановись.
2. **Пространство.** Если в проекте нет папки `borshkit/`, покажи путь текущей папки и спроси, здесь ли создавать пространство. Если это папка с исходниками самого Borshkit, предупреди и не создавай. После «да» выполни `borshkit начать`.
3. **Что уже есть.** Выполни `borshkit мастер --json`. Из поля `detected` узнай, какие программы (claude, codex, gemini) найдены на этой машине, из `draft` — что уже выбрано.
4. **Вопросы.** Задай через AskUserQuestion, пропуская то, что уже выбрано:
   - **Где ты работаешь:** `claude-cli` (Claude Code в терминале), `claude-app` (приложение Claude), `codex-app`, `vscode`, `other`. → `borshkit мастер вход <выбор>`
   - **Безопасность:** строгий (рекомендуется: работают только локальные модели и сервисы, которые не обучаются на твоих данных) или умеренный. → `borshkit мастер безопасность строгий|умеренный`
   - **Кто будет работать** (можно несколько): найденные программы из `detected` отметь как найденные; плюс API: `freellmapi` (свой сервер бесплатных лимитов), `ollama` (модели на твоём компьютере), `openrouter`, `groq`.
   - Для каждого выбранного: точный id модели; для `openrouter` и `groq` ещё семейство модели (meta, mistral, qwen…); политика данных аккаунта: `no-train`, `local`, `trains` или «не знаю» (`unknown`). → `borshkit мастер среда <имя> --модель <id> [--семейство <семейство>] --данные <политика>`
   - **Состав команды:** базовый (`architect,implementer,tester,reviewer`), для интерфейсов (базовый плюс `ui-engineer,designer,a11y-reviewer`) или свой список из `borshkit роли`. → `borshkit мастер роли <список>`
5. **Ключи API.** Для каждого выбранного API с переменной ключа (`FREELLMAPI_API_KEY`, `OPENROUTER_API_KEY`, `GROQ_API_KEY`) объясни, где взять ключ, и дай команду для его терминала: в Windows `setx ИМЯ "ключ"`, в macOS и Linux строку `export ИМЯ=ключ` в `~/.zshrc` или `~/.bashrc`. Напомни открыть терминал заново и перезапустить Claude Code. Для `freellmapi` сервер должен быть запущен, ключ — на его странице Keys.
6. **Итог и предложение.** Выполни `borshkit мастер` и перескажи коротко: что выбрано, какие роли кем закрыты и что мастер считает проблемой. Если проблем нет, выполни `borshkit мастер предложить`.
7. **Применение — за человеком.** Дай ему одну команду для его терминала: `borshkit настройки применить <номер предложения>`. Объясни, что Borshkit попросит ввести фразу подтверждения и почему агент не может сделать это сам.
8. **Проверка подключения.** Когда человек скажет, что применил, выполни `borshkit исполнитель проверить <имя>` для каждого исполнителя и перескажи результат. Если проверка не прошла, она называет причину: сервер не запущен, неверный адрес, ключ не принят или переменная не видна.
9. **Дальше.** Скажи, что следующий шаг — первая задача: `borshkit задача новая <имя> --цель "…"`, а подробности в `docs/guide/quickstart.md`.
