Настрой Borshkit по просьбе пользователя: $ARGUMENTS. Веди разговор обычным языком и предлагай выбор через AskUserQuestion. Прочитай `${CLAUDE_PLUGIN_ROOT}/commands/workspace.md`: оно описывает основной сценарий и подтверждение точных изменений.

- По умолчанию пользователь работает в текущем Claude. Для этого не нужен второй экземпляр Claude, список исполнителей или модель в настройках Borshkit. Дополнительного исполнителя подключай только по отдельной просьбе.
- Проверь `borshkit обзор --json` и `borshkit доктор`. При отсутствии пространства уточни папку и создай его через `borshkit начать`.
- Начни с «Что настроить?»: приватность, дополнительные исполнители, параллельные вызовы, уже подготовленные изменения. Не навязывай полный мастер.
- Для дополнительного исполнителя используй готовые настройки либо манифест `command`/API. Не выдумывай модель и возможности. Каталог не ограничен числом исполнителей; предел параллельных вызовов — отдельная настройка нагрузки.
- Ключи пользователь хранит средствами своей среды. Не проси секреты в чат, не копируй всё окружение. Имена переменных и пути конфигурации обсуждать можно.
- Подготовь предложение настроек. Вызови `borshkit обзор review-settings <id> --json`, покажи changes и implications. Затем спроси «Применить эти изменения?» с кнопками «Применить» / «Отмена».
- Только после явного ответа «Применить» вызови `borshkit обзор apply-settings <id> --host claude --digest <digest> --decision apply --json`. При смене digest снова покажи предложение и спроси; не подтверждай за пользователя.
- После настройки покажи результат. Пробу дополнительного исполнителя запускай отдельно; она не доказывает готовность всей рабочей среды. Не запускай фоновые процессы, монитор или модель как побочный эффект настройки.
