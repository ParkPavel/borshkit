Помоги пользователю в текущем Claude Code, включая терминал VS Code. Запрос: $ARGUMENTS.

1. Получи `borshkit обзор --json`. Если пространства ещё нет, уточни папку и создай его командой `borshkit начать`. Не создавай пространство в исходниках самого Borshkit без явной просьбы.
2. Покажи короткую карточку: **задача → текущий этап → последнее событие → что ждёт пользователя → доступное действие**. Предлагай через AskUserQuestion «Продолжить», «Проверить», «Показать процессы», «Настройки», «Остановить работу». Пользователь не обязан знать команды и идентификаторы.
3. Выполняй работу инструментами текущего Claude. Не запускай второй Claude, отдельный Codex, монитор или MCP-сервер только потому, что задача существует. Дополнительные исполнители и отдельный worktree нужны лишь по явному выбору пользователя. Описания ролей — подсказки, не обязательная регистрация текущего агента.
4. Для новой задачи уточни цель и критерии обычными вопросами. Создай допустимое техническое имя автоматически. Заполни контракт по согласованным ответам. Показывай реальные этапы, а не придуманные проценты. Полоса N/M допустима для проверок с известным количеством; «модель думает» не имеет достоверного процента.
5. Настройки: сформируй предложение, затем `borshkit обзор review-settings <id> --json`. Покажи изменения и последствия, спроси пользователя средствами текущей среды «Применить эти изменения?» с вариантами «Применить» и «Отмена». Только после явного ответа применить вызови `borshkit обзор apply-settings <id> --host claude --digest <digest> --decision apply --json`. Не подменяй ответ пользователя. Это доверенный вызов через разрешения харнеса, не криптографическое доказательство человеческого действия.
6. Процессы: `borshkit обзор --json --resources` измеряет зарегистрированные процессы по запросу. Показывай RAM и накопленное время CPU с временем наблюдения. Это не процент CPU, не полный список MCP и не жёсткий лимит. Внешними MCP управляет Claude; не завершай чужие процессы по имени или старому PID.
7. Остановка: выбери работу из снимка с canStop, затем `borshkit обзор stop <id> --json`. STOP_REQUESTED означает запрос, а не завершение. Обнови снимок и дождись STOPPED либо покажи, что подтверждения ещё нет. Не возобновляй автоматически.
8. После работы запусти согласованные проверки и покажи результаты отдельно от собственного заявления «готово». Сохраняй краткий итог и следующие действия. Не оставляй фоновые наблюдатели ради обновления карточки.
