# Как работать в пространстве Borshkit

Borshkit — рабочее пространство, где «готово» ещё не значит «принято». Принимает Borshkit — по доказательствам, привязанным к точному состоянию файлов. Где доказательства быть не может, принимает человек.

## С чего начать

1. Прочитай `borshkit/START-HERE.md` и `borshkit/STATUS.md`.
2. `borshkit статус` — режим приватности, задачи, что ждёт человека.
3. `borshkit знания контекст <задача>` — что в проекте связано с задачей.

## Правила

- **Не правь** `borshkit/settings/`, доказательства (`borshkit/tasks/*/evidence`, `logs`) и историю пространства. Настройки меняются предложением: `borshkit настройки предложить файл.json --от <твоё имя исполнителя>`; ослабление защиты подтверждает только человек.
- **Не объявляй задачу принятой.** Запусти проверки: `borshkit задача проверить <задача>`, затем `borshkit задача итог <задача>` и покажи человеку лист `acceptance.md`.
- Критерии классов: `auto` — решает проверка; `model` — твоё мнение, PASS требует доказательства `file:line`; `manual` — слепая зона, решает человек. Если что-то не проверено — так и говори: «не проверено».
- **Исследование:** каждый источник сохраняй командой `borshkit материал добавить …` (файл, `--url`, `--текст`, `--через jina`, `--команда`) и цитируй как `(источник: m-…, «точная цитата»)`. Источник, прочитанный в обход Borshkit, проверка цитат отклонит.
- **Git:** не делай `git push`, `git reset --hard`, `git clean -f`, `git branch -D`, принудительную отправку. Для человека есть `borshkit что-изменилось`, `кто-что`, `вернуть`, `собрать`, `отправить`.
- **Приватность:** не читай и не выводи секреты (`.env`, ключи). В строгом режиме ничего не отправляй наружу без явного «да» человека.

## Команды для работы агентов

- `borshkit роли` — роли команды и их навыки: `architect`, `implementer`, `ui-engineer`, `reviewer`, `simplicity-reviewer`, `designer`, `ios-designer`, `motion-reviewer`, `a11y-reviewer`, `researcher`, `tester`, `docs-writer`, `readme-designer`, `attribution-steward` и другие.
- `borshkit работа запустить <задача> --роль <роль> --исполнитель <имя> | --пул <пул>` — поручить работу исполнителю. Пишущие роли работают в отдельной копии проекта.
- `--навыки пакет/навык` — добавить к работе навык из `borshkit навыки` (например, `emil/animate`). Добавляй только то, что нужно задаче: больше текста не значит лучше результат.
- `borshkit библиотека [категория]` — проверенные первоисточники для интерфейса: Apple HIG, WCAG, WAI-ARIA APG, компоненты, анимация. Ссылайся на них, а не на память.
- `borshkit вопросы` — открытые вопросы. Критические решает только человек.
